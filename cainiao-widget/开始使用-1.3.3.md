# 菜鸟取件小组件 1.3.3 手机接入

**1.3.3 已发布。手机实际连接尚未验收。** 本版依据本人 iPhone 的实际 RPC 脱敏形状支持省略 `brand`。字段存在时保留原字符串，字段缺失时模板及独立 POST 均不添加它，其余合同和账号保护不变。

## 更新与运行

1. 更新原“菜鸟取件 · 原生小组件”远程模块及同一 JS，确认模块描述和 JS 首行显示 **1.3.3**。保持 `CONNECTION_MODE=auto`，手动 Cookie 留空，不重复添加同名模块。
2. 保留已有**菜鸟 App 自带的小组件**，等它下一次真实查询。没有官方组件时才添加一个，正常打开本人菜鸟 App 一次；不删除重装、不退出重登、不导 HAR 或复制凭据。
3. 在 Egern 小组件画廊运行**“菜鸟取件”**。实际 token 和模板已接受后，本组件才发带新时间戳的独立 POST；官方 App 的包裹响应不充当本组件更新。
4. 首次独立摘要查询成功后关闭菜鸟 App，再运行一次。第二次新请求成功才确认关闭 App 后可查询。系统自动刷新时机由 iOS 决定。

原模块“菜鸟连接状态”显示固定阶段、类型和查询次数，不显示 token、账号或包裹正文。不需要电脑或另装诊断。

## 已取得的证据

17:52 的 1.3.2 状态显示实际 RPC 已观察，唯一已知缺项为 `brand`；唯一包装、对象数量、数值版本、appName、五个安装布尔字段与 `V3` 均符合，根和对象额外字段均为零。该次只读取固定脱敏形状，没有读取 token 值或原始正文；当时独立查询与成功次数均为零。1.3.3 只修复这一具体差异。

实际候选、首次新摘要查询、关闭 App 后第二次新查询分别验收。bearer 仅表示专用凭据会话，不声称已核实 UID；新 token 不继承旧结果，已撤销 token 不复活。当前接口只接入官方摘要，完整列表、分页及结构化取件码尚未确认，不从描述数字猜码。详见 [README](README.md) 和[验证记录](验证记录-1.3.3.md)。
