# 菜鸟取件小组件 1.3.0 手机接入

**1.3.0 正在发布。手机实际连接尚未验收。** 这次增加真正的专用 token 捕获和独立包裹 POST，不是仅更改状态提示。协议已经从官方 Android 样本确认；是否适用于本人 iPhone 尚未验证。

## 已安装用户：只在手机操作

1. 更新原“菜鸟取件 · 原生小组件”远程模块及它引用的 JS，确认两者显示 **1.3.0**。保持 `CONNECTION_MODE=auto`，手动 Cookie 留空。不要同时启用两份同名模块；已有自己的 Egern CA 不用重装。
2. 主屏临时添加 **菜鸟 App 自带的小组件**，然后正常打开本人菜鸟 App 一次，让官方组件初始化。模块尝试在本机捕获它真正的专用 token 和实际查询参数，不需要电脑、HAR、复制字段或发出凭据。此步骤是为触发官方组件会话，不重复旧 Cookie 试验；iOS 是否产生同一合同仍未知，不保证仅此一步即可接通。
3. 回到 Egern 的小组件画廊，运行 **“菜鸟取件”**。两项实际合同齐全后，本组件会发自己的新 POST。否则会明确显示缺少专用会话或实际参数，不猜 Android 设备值、不伪装成功。
4. 关闭菜鸟 App，再运行本组件一次。若第二个新请求仍成功，即可只保留 Egern 的“菜鸟取件”桌面组件；后续有效 token 的查询不依赖打开 App，刷新时机由 iOS 决定。

不需要先运行发送对照或另装诊断。“菜鸟连接状态”只作为同模块的可分享状态，显示 token／模板存在性、新查询次数及固定错误，不显示 token、账号或包裹内容。如果没有接通，只反馈这里的文字即可；不导原始 HAR，不反复开关 App。

阅读器不支持 `egern:` 时，在 Egern 添加[远程模块地址](https://raw.githubusercontent.com/atopsecret/SurgeScripts/main/cainiao-widget/cainiao-widget.egern.yaml?v=1.3.0)。官方格式是 `egern:/modules/new?name=NAME&url=URL`。一条公开链接包含全部入口和自包含 JS，不需要本地文件；每个人的凭据只留自己的手机，不随链接分享。

首次没有 HTTPS 解密能力时，按 Egern 指引配置并信任自己设备的 CA。模块不能替用户信任系统证书，也不能自动将组件加到主屏。本版只在原四网关之外增加一个官方专用查询主机 `guoguouser.cainiao.com`，不启用全域解密。

## 这次能确认什么

- 实际捕获 token 和模板，只表示已取得新路线的候选；不等于查询成功。
- 主组件成功，是带新时间戳的**独立官方摘要查询**。不读取或复制菜鸟 App 的包裹响应来冒充更新。
- 关闭 App 后第二次成功，才确认本手机能在 App 关闭时独立查摘要。离线测试和代码发布都不代替此项。
- 数量采用官方待取计数；摘要只显示官方待取分类和描述。没有摘要但数量大于零时，仍显示“有待取，摘要未提供”。
- 此接口没有已确认的全量／分页和结构化取件码合同。摘要成功不代表完整待取列表或取件码目标完成，不从描述数字猜码。锁屏默认隐藏整个取件摘要。
- `INVALID_TOKEN` 明确停止，不把同值重复捕获当新凭据。Egern 不能自行运行菜鸟原生签发；服务端拒绝后仍需 App 重新接入。换号、退出或存储失败不会退回旧账号查询。

官方 iOS 如果不使用这两个接口或采用不同的参数，组件会停在未接通，不需要重复旧操作。这个缺口不能靠改版本号消除。详见[官方协议核对](官方小组件协议核对.md)和[本版验证记录](验证记录-1.3.0.md)。
