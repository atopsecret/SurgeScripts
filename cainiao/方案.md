# 菜鸟去广告：Egern 原生转换方案

## 来源与范围

- 用户要求将 Kelee 菜鸟去广告转换成独立 Egern 模块；不修改设备配置、不访问菜鸟业务接口。
- `https://kelee.one/Tool/Loon/Lpx/Cainiao_remove_ads.lpx` 于 2026-11-08 返回 HTTP 403，不能声称核实了原站当前最新版。
- 使用 `Moli-X/Tool@f4720ca1468bc5d97c7d6fc7771b894acf0770a1` 与 `fkingikelee/fkikelee@d62650fa4b5d8c03f65f03ff0ec2e8afed3226c0` 的固定镜像。两个插件的 `[Rewrite]` 及 `[MitM]` 活动部分相同，元数据不同；文件日期均为 `2026-10-02 13:57:49`。
- 活动插件只有四条请求 404 与四条内联 JQ，没有引用镜像中的 `Cainiao_remove_ads.js`。不将旧脚本的首页、工具保留名单、消息筛选和钱包删除计入本次迁移范围。
- 来源地址、哈希和活动规则取舍记录于 `sources.json`，不复制整份第三方脚本，也不推定统一许可证。

## 实现约定

1. 新建 `cainiao-adblock.egern.yaml` 与 `cainiao-adblock.egern.js`，版本 `1.0.0`。使用原生 `export default async function(ctx)`，不运行 Surge/Loon 兼容壳，不下载运行时公共脚本。
2. 将四条明确广告请求改为 Map Local 空体 404，保留来源的 HTTP 状态语义，附带本地版本头。主机与 Mtop API 名精确匹配，只允许空路径结尾、尾斜杠及数值版本路径（含 `/1.0/`），不使用来源宽前缀。
3. 页面响应只处理三个固定路由：两网关 `page.fetch`（含 `.cn`）的搜索热词及运营列表；`e2e-mtop` 的 `page.fetch.cn` 加清已知 banner、activity、vip；龙泉广告位 `780001` 的 `contentList`。列表或容器类型不符时保留，不创建缺失路径。
4. 不移植 netflow 的“首项 `materialId` 不是 `39017` 就把整个 `data` 清空”。该规则没有足够的逐项广告判据，可能删除未知业务。已知广告 index、show/mshow 请求仍由精确本地响应处理。
5. 保留查件、寄件、取件码、订单、包裹导入、钱包、权益、未知工具及其顺序。不开启泛域名封禁，不改 HTTPDNS、登录或服务端成功码。
6. 非 HTTP 200、非 JSON 媒体类型、非 UTF-8 声明不消费正文。正文使用 `arrayBuffer()` 单次读取与严格 UTF-8 解码；无变化、JSON/结构/业务错误及处理异常显式回传保存的原字节。
7. 只在正文改变时修改响应头：清过时长度、编码、缓存和校验信息，设置 UTF-8 JSON、`no-store` 与版本头；直接修改原 `Headers`，不枚举重建未触及的多值 Cookie 或业务头。头修改异常时尝试恢复并回传原字节，不承诺持续损坏的 API 可恢复。
8. Generic 诊断只输出固定路由、版本和封顶计数，不发通知、不请求网络、不保存 URL、Cookie、账号、取件码或响应内容。
9. 清理列表仅接受数组，运营卡片仅接受对象或数组；同名字段出现未知标量类型时保留。业务失败检查包含失败标志、非成功 `ret` 与陌生 `code`。只处理完整 HTTP `200`，不改部分内容响应。
10. 诊断只保存固定路由、结果枚举与有限计数，一次写入完成；响应头修改失败记为格式放行，不把未交付的改写计作成功。
