# 菜鸟取件小组件 1.2.3：手机更新

**1.2.3 已发布；模块和同一份 JS 已按原地址回读，版本与 SHA-256 一致。手机实际连接尚未验收。** 本版把接入检查和服务端 Cookie 候选采集放进原模块，不另装工具。它不是已经修好登录的承诺。

## 已经安装

1. 在 Egern 更新原有菜鸟取件模块和远程脚本。模块描述及“菜鸟连接状态”首行都要显示 **1.2.3**。保留 `CONNECTION_MODE=auto`；不填 Cookie，不重装已信任的 CA，不另建脚本。
2. 运行一次 **“菜鸟连接状态”**。脚本自动用固定假 Cookie 做 `omit/include` 发送对照，最多约十秒；不读取个人凭据，七天固定窗口内不重复请求。
3. 保持 Egern 与模块运行，正常打开已登录的**菜鸟或淘宝 App 快递／包裹列表，刷新一次**。不要退出账号，不要反复登录。原模块会采集合法响应 Cookie，并观察可能出现的三个已知登录接口结构。
4. 回 Egern 小组件画廊运行 **“菜鸟取件”**，紧接运行 **“菜鸟连接状态”**。把状态文字或截图反馈即可，不用 HAR、电脑或私人凭据。若显示个人查询已确认，再关闭 App 运行一次组件，验收它自己生成的新请求。

升级不会自动恢复 1.2.2 已经失败的候选。若这次没有捕获新的可用来源，原终止状态保留；发送对照的“已收到”也不能证明个人会话有效。

## 状态怎么看

- **发送对照**：两种模式分别显示测试标记是否收到、是否有额外 Cookie；超时、格式或存储错误显示未知，不猜测 Cookie 被剥离，不自动切换业务参数。
- **响应观察**：显示来源主机、固定接口类别、合法 Cookie 字段名、作用域与删除计数。已知登录正文只显示固定字段的类型／数量；没有出现这些接口不等于 App 未登录。
- **个人查询**：仍显示 `identity/count/pds` 阶段、固定失败分类及 token 是否更新。响应 Cookie 候选无论 H5/GW 都必须通过身份匹配、COUNT 和完整个人列表，才能确认连接。

仅保存脱敏结构与布尔结果，不显示 Cookie、UID、SID、签名、设备标识、原始 URL 或正文值。`FAIL_SYS_SESSION_EXPIRED` 说明这次独立请求没有接受候选，不等于 App 已退出登录。完整手机接入和关闭 App 后的新查询尚待此次结果确认。
