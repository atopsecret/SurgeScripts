# 扫描全能王 Egern 原生模块

## 目标与目录

将用户指定的 [Surge 模块](https://yfamilys.com/module/camscanner.sgmodule) 原生重写为 Egern 模块，并按仓库现有规范使用一个模块一个目录。模块、说明、方案、任务与专属测试统一归入根目录 `camscanner/`；`egern/` 仅保留公共索引和校验设施。

```text
camscanner/
├── camscanner.egern.yaml
├── README.md
├── 方案.md
├── tasks.md
└── tests/
    └── test_camscanner.py
```

## 来源与功能合同

- 原模块及活动引用的 [NobyDa 脚本](https://raw.githubusercontent.com/NobyDa/Script/master/Surge/JS/CamScanner.js) 初次检查均 HTTP 200。原脚本解析 JSON 后覆盖整份响应，只固定输出 `data.psnl_vip_property.expiry = "2013017600"`。
- 使用 [官方原生 `body_rewrites.response_jq`](https://egernapp.com/docs/configuration/body_rewrites/)，不引用外部 JavaScript，不使用 Surge 全局变量或兼容壳。
- 仅匹配 `api.intsig.net`、`api-cs.intsig.net` 的精确 HTTPS 查询接口；接受无查询串和显式 `:443`，拒绝其他端口、伪装主机、用户信息、接口后缀、子路径与 URL 片段。
- 到期值及字符串类型保持 `"2013017600"`。仅改该字段，保留顶层、`data` 与会员对象的其他字段；`data` 为对象时允许创建缺失或空值会员对象。
- 顶层或 `data` 不是对象、会员对象为未知标量或数组时，JSON 结构保持不变。不新增或覆盖服务端结果码。原生 jq 不读取 HTTP 状态，无效 JSON 的客户端处理须真机核实。
- MITM 使用官方完整配置示例中的 `hostnames.includes`，仅包含两个实际匹配的主机；不复制证书，不解密整域，不添加全局 QUIC 拒绝。
- 保留 NobyDa 署名与来源。公共校验器继续使用十一模块清单；专属测试留在本模块的 `tests/`，不混入公共校验目录。

## 目录整理合同

1. 迁移完整文件，不保留旧位置的副本或兼容入口。
2. 更新模块主页、使用说明地址、Raw 链接、一键导入链接、首页索引、公共索引、校验器与测试加载路径。
3. 迁移前保存规则和 MITM 配置的结构基线；迁移后逐项比较，确认只有位置、元信息和测试路径变化，改写功能不变。
4. 增加目录布局回归，检查模块资料归属独立目录、旧位置无文件以及索引使用新地址。
5. 运行专属 jq、公共静态与原有脚本回归。普通推送 `main` 后按新 Raw 地址回读字节并核对 SHA-256，不改其他模块目录。
