# 菜鸟取件小组件 1.3.2 手机接入

**1.3.2 正在发布。手机实际连接尚未验收。** 本版修复已复现的首次迁移缺陷：旧 H5 受限会话正常采集会留下隔离标记，1.3.1 可能因此忽略随后出现的官方查询。合法实际 RPC 现在可以建立全新的专用凭据会话，旧官方账号、冲突和撤销屏障仍受保护。

## 已安装用户

1. 更新原“菜鸟取件 · 原生小组件”远程模块及它引用的 JS，确认模块描述和 JS 首行都显示 **1.3.2**。保持 `CONNECTION_MODE=auto`，手动 Cookie 留空。不要重复安装同名模块。
2. 保留主屏已有的**菜鸟 App 自带的小组件**，等待下一次实际刷新。没有官方组件时才添加一个，正常打开本人菜鸟 App 一次。无需删除重装、退出重登或重复旧 Cookie 试验。
3. 在 Egern 小组件画廊运行**“菜鸟取件”**。接受实际 token 和模板后，本组件才发送带新时间戳的独立 POST；不复制官方 App 的包裹响应作为更新。
4. 首次独立摘要查询成功后，关闭菜鸟 App，再运行一次。第二次新 POST 仍成功，才确认本手机能在 App 关闭时查询；系统自动刷新时间由 iOS 决定。

不需要电脑、HAR、复制凭据或另装诊断。原模块中的“菜鸟连接状态”可显示固定采集分类与已知字段类型，不显示 token、账号或包裹正文。正文未接受时只反馈此处文字，不靠反复重装消除协议差异。

## 当前证据与验收边界

2026-11-09 已在本人 iPhone 确认官方 `WidgetExtension` 向精确 `queryWidgetDetailsV2` 地址发出新 POST，现有 MITM 命中。1.3.1 已更新到手机，但新连接出现后主组件仍未接通。独立合成随后复现旧 H5 屏障阻挡首次 bearer 接入；不把该本地缺陷认定为手机唯一根因，也不把 HTTP 200 当业务成功。

1.3.2 首次迁移只接受严格已知的旧 capture 屏障，合法实际查询才替换为新的 bearer 屏障；未知正文只保留固定脱敏形状，旧屏障不动。bearer 表示专用凭据会话，不声称已核实 UID。新 token 不继承旧缓存或成功计数，已撤销 token 不被迟到请求恢复。

以下项目分别验收：实际候选和模板被手机接受、本组件首次新摘要查询、关闭 App 后第二次新查询。当前接口只接入官方待取摘要，完整列表、分页和结构化取件码尚未确认；不从描述数字猜码，锁屏默认隐藏整个摘要。详细边界见 [README](README.md) 和[验证记录](验证记录-1.3.2.md)。
