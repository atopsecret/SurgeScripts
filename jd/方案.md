# 京东 2.0.0 双端补全方案

## 范围与基线

2026-11-08，按用户确认落实京东对照建议。仅修改京东目录；不访问真实京东接口、不修改客户端配置。修改前京东 Egern 回归 **44/44**。根代理管理全仓基线与发布。

## 匹配与请求身份

- 显式列出 `uniformRecommend`、`uniformRecommend0`、`uniformRecommend6`，不使用接口名前缀猜测。
- 静态规则允许目标参数位于任意位置，要求完整值边界与唯一目标键；参数键若含百分号编码、加号或陌生字符则保守放行，防止正则与解码器对重复键理解不同。普通参数值仍可包含合法编码。
- 响应分发使用同一纯函数解析，拒绝重复或非法 `functionId`。查询中已有该键时，不回退到 POST 正文。POST 表单与 JSON 均仅接受唯一明确 ID；JSON 顶层重复键（包括转义后相同键）拒绝。
- Surge 官方响应脚本输入没有请求正文，不能直接读取 `$request.body`。响应入口默认处理带已知查询 ID 的请求。无查询 ID 的 POST 关联脚本在模块中整行注释，不对所有业务请求启用；用户明确启用后只覆盖没有查询字符串的 `/client.action`，按官方稳定 `$request.id` 读取 POST 正文，使用 32 MiB 硬上限。超限请求会被 Surge 终止而不是跳过，也有额外内存开销。出站 URL、头与正文不变；默认关闭不会增加未知大请求被拒绝的风险。
- 跨阶段缓存仅保存请求 ID、固定接口名和 60 秒到期时间，最多 64 项；消费后删除，无稳定 ID、缓存缺失、读写失败或过期时放行。存储没有 CAS，并发可能丢更新，只允许漏处理，不猜测身份，不承诺绝对跨进程关联。

## 共用策略与页面处理

同一 `jd-policy.js` 是业务策略唯一来源；构建时内联成独立 Surge 与 Egern 文件，不新增客户端远程公共运行时。

- 保留开屏字段级清理、首屏、购物车、二楼、极速版和导航功能。
- 同步 basicConfig 根层与 data 包装、HTTP/业务失败放行、lite 只改键名且保护冲突、混合列表容错。
- 导航文字协议仅排除已知视频标签，保留未知入口和相对顺序，清理后至少保留两个项目。旧 ID 协议只排除来源可证的 `video`，保留未知工具和相对顺序，并继续要求 `index`、`cart`、`home` 完整。
- 新增 `orderTrackBusiness` 物流别名、`getTabHomeInfo` 新品推广、`myOrderInfo` 订单推广、`personinfoBusiness` 已知促销楼层与弹窗。
- 不复制个人工具栏白名单与排序；不修改客户服务提示、评价提醒、钱包、正常订单和未知模块。
- 独立模块 MITM 包含 API、素材、短视频组件及两条 ADX 精确主机。

## 正文与响应头保护

- Egern 单次 `arrayBuffer()`；Surge 使用官方 `binary-body-mode=true`。严格解码 UTF-8，无效编码、未知 JSON、业务失败和无变化返回原字节（Surge 可直接放行原响应）。不改写声明非 UTF-8 的内容和非 JSON 媒体类型。
- 仅有变化才序列化。移除旧长度、压缩、校验与缓存头，设置 JSON UTF-8、no-store 和版本头。
- Egern 直接修改原 Headers，不枚举重建多值头；修改异常时尝试恢复触及的头并回传原字节。Surge 使用 `full-header-mode=true`，逐项保留未触及的重复头及原顺序。
- 读取失败没有完整原字节可恢复，不二次读体、不伪造正文。
- HTTP 响应仅处理完整的 `200`，不重写 `206` 分段响应。JSON 序列化或策略异常也在已消费正文的保护内；无变化与异常一律显式返回 `Uint8Array`，不用文本回退代替原字节。
- 构建检查同时识别缺失产物与内容过期；脚本版本只替换 URL 的 `v` 参数，不吞掉模块说明。

## 验证与发布边界

新增 Surge、Egern、共用策略及双端一致性回归；覆盖静态参数边界、编码键、JSON 重复键、POST 关联隔离、TTL/容量与存储异常、UTF-8/媒体类型、一次性流、响应头、多值 Cookie、四个新增接口、业务保留和幂等。

Surge 需要当前官方文档所列的稳定请求 ID、二进制正文和完整头模式；未核实这些 API 在全部旧版本上的最早可用版本，不伪造最低版本号。离线测试不代表手机导入、CA 信任、开屏缓存或所有账号页面已验收。
