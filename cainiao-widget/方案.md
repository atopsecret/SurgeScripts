## 1.2.3：在原模块取得手机接入证据

2026-11-09 用户在了解发送对照、服务端 Cookie 与登录／续登结构核验后明确要求“那你去干啊”，授权将这些检查接进现有小组件并按本项目持续发布约定上线。本轮不再只写研究结论，也不交独立诊断、HAR 工具或电脑脚本。版本为 1.2.3；新增取证和真实响应 Cookie 候选，不宣称 1.2.2 的 SESSION 拒绝已经解决。

### 发送对照

- 原模块“菜鸟连接状态”首次运行时，在 `auto` 模式用固定合成 Cookie 向固定 HTTPS 回显地址 `https://postman-echo.com/headers` 分别发送 `omit/include` 请求。请求仅由常量构造，不读取或复制自动／手动凭据、App 头、原始 URL 或个人查询参数；测试域与淘宝／菜鸟域分离，不扩展 MITM。禁止重定向，TLS 验证保持开启，每次 HTTP 超时四秒，总预算十秒。
- 保存的只是两次回显的固定结果分类、测试标记是否收到的布尔值、是否出现额外 Cookie 的布尔值及时间。服务端回显的 Cookie、头值、异常原文与正文不进入存储、日志或组件输出。有效回显不能证明淘宝网关会话有效，也不自动将生产查询切为 `include`。
- 用本组件独立键保存短租约和结果，写后回读确认；未取得存储归属时不发测试请求，并发或模式变化时不回写旧结果。结果有效七天，同窗口不重复发请求；网络或格式错误明确为未确认，不将失败猜成 Cookie 被剥离。手动、关闭和 HTTP hook 入口不运行对照。当前只读诊断函数仍保持只读，由原生 generic 入口显式启用一次性检查。

### 服务端响应 Cookie

- 同四个精确 HTTPS 主机新增无正文响应 hook，只读取实际 `Set-Cookie`。普通 `mtop.*` 使用无正文入口，三个已知 `com.taobao.mtop.mLoginUnitService.*` 使用单独正文入口；两类响应匹配互不重叠，不依赖 Egern 对重叠响应脚本的未文档化执行顺序。已知正文入口先做相同的响应头检查，再只记录结构；每次响应最多采集一次候选。保留所有原始响应头和正文，不修改查件结果。Cookie 名仅允许现有七项认证字段；字段数、头大小、重复属性、合并头、到期和删除均有界处理。
- 必须同时满足响应来源域合法，以及 Cookie 实际可用于固定 H5 身份、COUNT、PDS 三个路径；拒绝跨来源 Domain、错误 Path、其它域和无 Domain 的其它主机 host-only Cookie。不将菜鸟域的 Cookie 摊平到淘宝，不借旧会话或其它响应拼接值。
- 只有同次响应含可用 `cookie2/sgcookie`，且响应 `unb` 或同次请求的实际 UID 有效、无冲突时，形成新的 `response_cookie_candidate`。UID 只用来约束候选，不是认证成功。该来源无论 H5/GW 都必须经过个人身份匹配、COUNT、完整 PDS 才能确认；不以 token、公开时间或任意 SUCCESS 确认连接。
- 增加 auth helper，保留已有账号屏障、代次、写后回读、失败终止和强候选优先级。相同响应候选的终止状态不被重复响应复活；新稳定会话才形成新代次。另一账号候选写失败后，旧稳定响应仅更新 token 也不能撤销新账号屏障或恢复旧代次查询。新候选不得携带旧 token、快照或跨请求身份。已确认的同账号完整请求 Cookie 不被响应试探降级。
- 请求路由、采集和响应候选共用严格头读取；文档化 `getAll/get` 与普通对象都执行大小、类型、重复值和控制字符检查，普通对象不能在响应层看得到 UID、在 auth 层却丢掉身份约束。

### 登录／续登结构

- 仅在旧公开 SDK 已明确出现的 `com.taobao.mtop.mLoginUnitService.login/autoLogin/logout` 精确路由增加单独有界正文 hook。它只记录固定路径的类型、数组数量、固定返回分类和是否出现 Cookie／UID 字段，不提取正文登录凭据，不假设当前 iOS 采用旧 Android schema，也不递归搜索任意正文。
- 正文解析最多二百五十六 KiB，只接受有限层级的已知 JSON／JSON 字符串封装。模块设置同样的 `max_size`，对明确超限长度不读体；Egern 的 `arrayBuffer()` 不支持流式硬截断，未知长度实际超限时只透传已读取字节、不解析。二进制、压缩、HTML、未知结构和读体错误均如实分类；读到的原始字节必须原样返回，不更改响应头。其它 MTOP 响应仍不读取正文。未观察到已知续登接口不等于 App 未登录，也不要求反复开关或退出账号。
- 响应元数据只保留精确主机、固定 API 类别、字段名／固定结构路径、计数和时间；最多三十二行、七天窗口。未知字段和服务端文本不展开，不记录 Cookie 值、账号、SID、签名、设备标识、完整 URL 或个人正文。

- COUNT 的 `SUCCESS` 不是单独的登录证明。原生候选还需获得个人身份接口的可核验账号结果，在内存与捕获 UID 比对；随后 COUNT 和完整 PDS 都成功才确认兼容。零包裹也遵守相同验证，不能由公共时间、访客 token 或成功状态码推导本人空列表。
- 身份接口固定为 `mtop.user.getUserSimple`、`data={}`。官方 lib-login 2.2.3 可核对请求参数；官方 myexpress 0.0.8 消费顶层 `userNumId`，并不证明当前 H5 的稳定 schema。实现仅接受该顶层字段的正十进制字符串／正安全整数并与捕获 UID 相同；缺失、零、别名、不安全数或不匹配均不确认，不用昵称、输入 Cookie 或 COUNT 补判。
- 新状态记录 `captureKind`、`sourceChannel` 和账号检查时间；迁移只接受通过原 1.1.0 全部校验的 Cookie 状态，不改 owner、代次、token 或已有快照。新写入必须回读确认当前版本及来源字段。
- 四主机路由只接受精确 HTTPS 443 URL；若实际 `Host` 存在，必须与 URL 一致。仅调用公开 Headers API 支持的普通头名，不依赖未承诺的 `:authority` 读取能力。头数量、大小和冲突均有界检查。
- 组件内部观察固定最多三十二行；七天窗口从首次观察开始，后续流量不续期旧证据。名称并集与同次登录组合分别保存，通用入口只显示白名单清洗后的结果。不新增 response hook，也不读取 App 正文。
- 所有业务查询同属十八秒预算，每次请求另生成新时间戳和签名；身份检查、COUNT 与 PDS 共用 token 更新及账号／执行归属检查。网关 Cookie 仅在固定主机和实际业务路径可用时吸收，不跟随重定向。

### 本轮实现约束

- 请求捕获、组件和只读连接诊断引用同一个自包含脚本 URL；请求入口不返回值，原样透传。原生 `Headers.getAll()` 逐条读取 Cookie，拒绝冲突重名，不消费正文。`storage.getJSON/setJSON` 按官方同步 API 使用，减少不必要的异步交错。
- 本机自动凭据、取件快照和不含敏感信息的捕获结果分开保存。自动凭据只保留 `unb`、`cookie2`、`sgcookie`、`munb`、`_m_h5_tk`、`_m_h5_tk_enc`、`_tb_token_`；不保存昵称和无关追踪 Cookie。自动凭据必须有账号标识和会话 Cookie，后续仍以个人接口结果确认是否可用。
- `CONNECTION_MODE` 默认 `auto`：优先自动凭据，未捕获时允许旧手动参数作为备用。`manual` 禁用捕获并只用手动参数；`off` 禁用捕获，下一次组件执行清空本组件登录态与快照。错误的模式不发业务请求。
- 捕获记录有账号摘要、稳定会话摘要、代次和输入摘要。网关 token 更新改变输入摘要，不改变会话代次，也不清同账号快照；账号变化先清旧快照。过期或身份失效后，必须经过新的手机请求捕获才重新尝试。
- 在每次业务请求、写缓存及返回结果前复核自动凭据代次和输入摘要。途中出现新捕获时停止旧任务，不覆盖新凭据、不回显旧账号包裹。同步回读检测静默写入失败；不把失败写入报为捕获成功。
- 已成功写入本轮状态后，也检查快照键的归属；关闭连接或另一任务写入新账号时，旧手动/自动任务不得在之后恢复已清除的快照。存储 API 不可用时只能显示本次实时结果并提示，无法承诺跨进程取消。
- 新账号捕获先在快照键写入带目标账号摘要的隔离屏障并回读，再写候选凭据。候选写入失败时保留屏障，后续刷新不得继续使用旧账号；新账号保存和查询成功后用其正常状态替换屏障。不能只清快照而遗留可恢复查询的旧登录态。
- 手动空参数不得清除已存在的账号屏障；自动模式读取快照/屏障 API 失败则停止个人查询，不能把未知存储当作无屏障。明确的 `off` 退出会同时清自动凭据和屏障。
- 每次刷新另有执行摘要，区别同账号、同 token 的并发刷新；新任务接管后旧任务不得写回更早快照。自动模式每次吸收网关 Cookie 后仍过滤相同凭据白名单，响应里的昵称和追踪 Cookie 不进入本地缓存。
- 本地存储没有公开的事务或跨脚本作用域保证。同 URL 和命名空间是实现方式，不当作真机共享已经验证；多进程竞态及系统仍显示的旧 timeline 无法靠脚本彻底消除，必须列入手机验收。
- 默认安装说明只包含手机：导入模块、信任本人 Egern CA、打开官方手机查件页并登录、回到组件刷新。淘宝原生桥未触发 H5 时保持未捕获提示，不承诺打开淘宝首页就一定连接。独立 Python 助手仍保留为开发工具，不进入默认引导。
- `setup` 可附短标题 `setupTitle`，区分未连接、关闭连接、手动参数缺失及本机存储异常；关闭连接时不继续要求用户打开查件页。
- 只读连接诊断也读取账号隔离屏障；旧登录态被阻断时优先显示阻断原因，不继续把先前查询成功当作当前账号已连接。

## 目标

在 Egern 原生小组件中清楚显示待取数量、取件码、驿站、快递公司和运单尾号。桌面采用蓝色强调与自适应浅深色背景，取件码优先；锁屏默认隐藏取件码，避免公开个人取件凭据。独立于菜鸟去广告模块，不改写物流业务响应。

## 数据与登录

- 使用公开源码可核实的淘宝 H5 MTOP 账号接口，不用短信读取或未文档化的 Egern 能力。
- 个人包裹接口为 `mtop.cainiao.lpc.packageservice.queryPdsPackageDataList`，固定 `appKey=12574478`，签名为 token、毫秒时间戳、appKey 与原始紧凑 JSON 的 MD5。
- 固定请求域名为 `h5api.m.taobao.com`，只接收该请求的 Cookie 更新；不自动跟随业务响应跳转，不把凭据发往第三方。
- 首次接入优先手机淘宝／菜鸟 App 快递列表与同一组件的请求采集；不要求查件网页、HAR、电脑扫码或粘贴。独立 Python 助手仅保留为开发工具，不进入默认流程。
- 自动模式优先使用本机捕获凭据，未捕获时允许 `CAINIAO_COOKIE` 手动备用；网关 Cookie 更新保存在设备本地。参数不是加密保险箱，导出配置可能包含凭据，说明文档明确标识。
- 旧独立登录助手仅允许 HTTPS 的淘宝、天猫、菜鸟登录域族，Cookie 遵从域和路径，逐跳校验重定向，限时、限跳；登录收尾后必须检查账号接口成功才输出凭据。

## 状态与缓存

- 有效真实取件码优先判待取；过滤 `NEEDSMS`、`0`、`-1`、`null` 等哨兵，保留需验证说明，不把驿站代收当本人已领。
- 分页有总时限和页数上限。全部查询成功才更新完整快照；部分成功保留历史并标明数据未取全，不冒充准确总数。
- 未登录、登录过期、风控验证、网络失败、未知结构均有独立提示。失败保留上次快照和原更新时间，不显示为零件。
- Cookie 导入内容变化时优先采用新凭据；以账号身份摘要隔离缓存，缺少可靠账号标识时以会话摘要隔离。更换账号不会展示旧账号包裹。
- 仅缓存展示必需字段，不记录完整响应、地址、姓名或完整运单号，不写入日志。
- 默认建议十五分钟后刷新，服从 iOS 调度；不承诺实时、不提供虚构的点击复制或领取按钮。

## 显示合同

渲染入口为 `renderWidget(model, family, now)`。模型字段为 `status`、`items`、`total`、`updatedAt`、`message`、`privacy`、`refreshMinutes`，可选 `partial`。条目字段为 `id`、`code`、`station`、`company`、`tail`、`requiresVerification`。

- `status`：`ready`、`setup`、`expired`、`offline`、`verify`、`partial`、`error`。
- `total` 是当前可确认待取条目数；`partial` 时数量标为“至少”，不能展示为完整数量。
- 小尺寸突出第一件，中尺寸显示两件，大尺寸显示四件，超大尺寸显示更多；超过可视范围明确显示剩余数量。
- 空列表、缺码、长站名、超长码与多件均要布局检查。锁屏三种尺寸显示数量/状态，只有显式打开隐私选项后才显示码。
- 1.2.0 不把官方查件网页作为点击入口；未核实 App scheme 时不设置组件 `url`，不伪造详情页。
- 使用官方文档 DSL 字段，原生与离线预览共享同一棵 DSL。预览使用合成数据并标明“离线预览”，不当作真机截图。
