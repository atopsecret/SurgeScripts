# 菜鸟 App 首次接入：1.2.1 后续协议核对

本记录保留签名修正发布前的研究与测试快照。该修正现已纳入 1.2.2，正在发布；当前进度见[1.2.2 验证记录](验证记录-1.2.2.md)。下文的“未发布”指本次研究结束时的状态，不把它改写成当时已完成手机接入。

## 当前结果

线上 1.2.1 已发布，十三个原地址最终回读均为 HTTP 200、与提交同字节。用户手机已确认保存同次 App 实际 Cookie，首次 H5 身份请求仍返回 `FAIL_SYS_SESSION_EXPIRED`。没有继续 COUNT 或 PDS，不能称为独立接入成功，也不能据此认定 App 已退出登录。

本轮找到并修正了一个本地签名错误：没有 `_m_h5_tk` 时，应与官方 SDK 一样拼接 `undefined`，而不是空串。这个修正未发布，不代表此次 H5 会话拒绝已经解决。仍保留身份匹配、COUNT、完整 PDS 和失败停止逻辑。

本报告只使用用户发来的脱敏状态、公开 JS、固定 Android SDK 静态分析和官方文档。没有读取私人 HAR／凭据，没有执行 SDK或上游源码，没有在电脑上请求个人接口，也没有改手机配置。

## 官方 H5 首次签名

官方 [lib-mtop 2.7.4](https://g.alicdn.com/mtb/lib-mtop/2.7.4/mtop.js) 原地址 HTTP 200、无跳转，共 28,654 字节，SHA-256：

```text
828024bfe8274ad4950f4c3ec0707a97c69eb17767fa9dc13941c1d4646cfe69
```

0 起始的解码字符位置：Cookie 读取器在约 5123 处没有命中时返回 `undefined`；10196 处读取 `_m_h5_tk`，存在时取首个下划线前缀；12397 处按字符串拼接计算签名。

```text
缺 token：MD5("undefined&" + T + "&12574478&" + 原始紧凑 DATA)
有 token：MD5(TOKEN_PREFIX + "&" + T + "&12574478&" + 原始紧凑 DATA)
```

签名之后才对 query 编码。`_m_h5_tk_enc`、UID、SID 和其它 Cookie 都不是此公式的 token。非空原值 `_123` 经切分得到空前缀，不能把这类结果再次替换成 `undefined`。

官方 [2.6.1](https://g.alicdn.com/mtb/lib-mtop/2.6.1/mtop.js) 同样如此；SHA-256 为 `f0003858b0c78be11b20615b4c7bff169f72a6e6d1e8c39f81ce66cefe8c182f`。本轮以实际请求声明的 2.7.4 复核，不能只凭 `jsv` 标签推断源码。

## Token 更新不等于账号授权

官方 MTOP 首次没有 token 仍直接发业务请求。token 类失败后重读 Cookie，有界重试；没有一条通用的公共时间请求能证明个人会话已建立。

`SESSION_EXPIRED` 等失败进入另一条登录中间件。满足登录选项时，SDK 调用 `lib.login.goLoginAsync()`，依赖网页登录、iframe 或 App 内的 `aluWVJSBridge.sdkLogin`。登录成功后才重新读取 token 并发请求。仅增加 `sessionOption` 或拿到任意 token，不能替代这一过程。

[lib-login 2.2.3](https://g.alicdn.com/mtb/lib-login/2.2.3/login.js) 的身份请求包含 `getUserSimple`、`ecode=1` 与 `AutoLoginOnly`。`AutoLoginOnly` 在 native 通道被传给 `MtopWVPlugin.send`，并非独立 HTTP 会话兑换协议。

[官方 myexpress 0.0.8 页面](https://cn.alicdn.com/guoguo/app-myexpress-taobao/0.0.8/index.js) 用普通 MTOP 请求消费顶层 `userNumId`。普通请求在 App 环境可以走 WindVane；这不证明当前独立 H5 返回相同结构，也不能凭页面前缀 `acs` 推断换主机就会恢复会话。

[Egern 官方 API](https://egernapp.com/zh-CN/docs/javascript-api/)提供网络 hook、HTTP 和持久存储，没有提供在菜鸟／淘宝进程调用上述原生登录桥或 SecurityGuard 的 API。公开文档未提供的能力，不能当作模块已经具备。

## 原生 SDK：SID 与 Cookie 是不同产物

固定来源：[mimicode/albcpackage 的 SDK 副本](https://github.com/mimicode/albcpackage/tree/e4275a7bb8dfc226490e1f30bb90c5ba3dbb41ab/libs)，提交 `e4275a7bb8dfc226490e1f30bb90c5ba3dbb41ab`。三个文件 SHA-256 与 `sources.json` 一致。它是第三方保存的旧 Android SDK，不是当前 iOS wire 格式保证；不捆绑或执行 SDK。

以下定位为方法内字节码偏移，不是 Java 源码行号：

- `CredentialManager.refreshWhenLogin @36–45` 解析服务端 `LoginReturnData.data` 为 `LoginDataModel`；`@435–442` 注册模型的 SID／UID；`@500–504` 注入模型中的 Cookie。不是从 SID 生成 Cookie。
- `LoginServiceImpl.autoLogin` 要求已经保存的 `autoLoginToken` 和 `user.userId`。`LoginComponent.loginByRefreshToken @10` 调用 `com.taobao.mtop.mLoginUnitService.autoLogin`，另有应用和设备上下文；条件分支 `@277` 调用安全组件签名。不能用 H5 appKey 与 MD5 代替。
- `getway` 是 Android Intent 与 `tbopen://m.taobao.com/getway/oauth?` 授权流程，涉及注册应用和应用签名，不是提交 SID 的普通 HTTP 兑换地址。

官方[媒体接入准备](https://developer.alibaba.com/docs/doc.htm?treeId=129&articleId=118101&docType=1)和[iOS 5.x 文档](https://developer.alibaba.com/docs/doc.htm?treeId=129&articleId=118593&docType=1)要求应用注册、安全图片、Bundle ID、SDK 初始化及授权回调。原生授权结果与可导出的 H5 Cookie 不是同一回事。

## 同模块被动捕获登录响应：仍需当前 iOS 证据

旧 Android 解析路径可定位为：

```text
MTOP 根 data.returnValue
  → LoginReturnData
  → LoginReturnData.data
  → LoginDataModel.userId / cookies:string[]
  → 按 Cookie 的 Domain/Path 注入 WebView
```

这是比 SID 映射更可靠的候选来源，但尚未实施：

1. 必须先确认当前 iOS 的实际登录 API、响应形状、编码与触发条件。已登录 App 打开快递列表未必续登。
2. 只解析该登录 API 的同次成功响应，校验外部 MTOP、内部登录结果和 UID；不能递归搜任意正文里的 `cookies`。
3. 保留必要 Cookie，遵守实际 Domain/Path，不从 SID 造 Cookie，不与其它请求或旧账号拼接。
4. 旧 SDK 的 `externalCookies` 是额外目标域数组，不是第二份登录凭据；不能据此扩域。
5. 登录正文仅短暂留内存，不写原文、账号资料或其它 token。原响应原样透传，不读取无关包裹正文，不另装诊断模块。
6. 仍须账号隔离、写后回读及本轮身份／COUNT／完整 PDS；采集成功不能代替独立查询成功。

旧解析层直接处理 JSON，只证明 SDK 交付给该层的数据，不证明当前 iOS 网线上一定是同样的明文结构。缺少这些证据时，不扩大 hook、不猜字段、不宣称已完成 App 一次接入。
