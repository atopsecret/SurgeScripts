# 菜鸟去广告 1.2.0：HTTP/3 与自营开屏

日期：2026-11-08，Asia/Shanghai。基线为双端 `1.1.1`，提交 `a975d81b2669166434502a6b56e46e29c4198eee`。本次版本：Surge `1.2.0`，Egern `eg-native-20261108-1.2.0`。

## 为什么图片补漏后仍有广告

第三份 HAR 共 147 条请求，Surge iOS `5.23.0` 导出，时间范围 `20:18:50–20:19:06`。配套 PCAP 共 11,844 个包，时间范围 `20:18:48.564693–20:19:20.199078`。

### 自营视频与备用封面

HAR 中，`a1.alibabausercontent.com` 的一个 MP4 成功返回 HTTP `200`，572,240 字节、5 秒，视频分辨率 1126×2436。已提取并查看视频帧，内容为“天猫双 11 品类周／李佳琦直播间超级生活节”。该资源不经过之前的 `p3-sign.douyinpic.com` 图片规则。

本地解压日志请求的 LZ4 正文并读取 Protobuf，得到 343 条应用记录。`Page_Screen_Cpm` 的 `ScreenCpmDataResponse`、`ScreenCpmEntry`、`ScreenCpmExp` 和 `RtbAdsCostTime` 明确关联该视频与 `ossgw.alicdn.com` 的 JPG 备用封面，`source=100`。日志还关联另一个预取视频和封面，共四个不同的素材地址，并出现一次 `isCache=true`。

因此，既有新视频下载，也有缓存复用证据。仅补图片素材，或把所有剩余展示归因于缓存，都不足以解释本次记录。

### 原生接口走 HTTP/3

解压日志中的 65 条 `CN_Mtop` 记录，有 60 条标记为 `http3`，另 5 条为 `http2_0rtt_acs`。其中包含广告接口和原有页面清理接口；这些具体请求未出现在普通 HAR 请求列表中。

PCAP 中存在版本 `ff00001d` 的 draft-29 QUIC。按该版本的公开 Initial 密钥派生方法解析客户端握手，成功解密 24 个 Initial 包，并识别 24 条连接的 ClientHello SNI。没有解密 QUIC 应用正文。

可识别主机包括 `netflow-mtop.cainiao.com`、`cn-acs.m.cainiao.com`、`e2e-mtop.cainiao.com`、`nbcps-mtop.cainiao.com` 和 `longquan-mtop.cainiao.com`。这与应用日志的 HTTP/3 记录互相印证，普通 HAR 的规则覆盖数不能单独证明原生广告 API 已被处理。

### 广告 API 路径也有遗漏

日志确认以下路径变体：

- `netflow-mtop.cainiao.com`：`mtop.cainiao.guoguo.nbnetflow.ads.index.cn`、`ads.mshow.cn`。
- `cn-acs.m.cainiao.com`：`mtop.cainiao.guoguo.nbnetflow.ads.mshow.cn`、`mtop.cainiao.adx.flyad.getad.cn`。

旧规则不包含这些 `.cn` 变体与 flyad 接口。即使请求回退到普通 HTTPS，也需要补齐路径。

本次日志有 52 条请求明确命中“菜鸟去广告”的既有规则。由于没有出现上一版目标图片或版本响应头，不能仅凭此判断手机是否已加载 `1.1.1`；以上遗漏在 `1.1.1` 源码中同样存在。

## 本次修改

原生拒绝条件由 17 条增加到 20 条：

1. 对本模块九个精确 MITM 主机使用 `PROTOCOL,QUIC` 条件拒绝，促使请求重试 TCP。保留其它主机及目标主机上的 TCP，没有修改全局 QUIC、DNS、HTTPDNS 或系统设置。
2. 对 `a1.alibabausercontent.com` 的 `/prod/feupload/user/7clgu/` 目录下 `*.mp4_.mp4` 文件添加菜鸟 UA 条件。
3. 对 `ossgw.alicdn.com` 的 `/creatives-assets/prod/feupload/user/7clgu/` 目录下 `*.jpg` 备用封面添加相同 UA 条件。

素材按目录与格式匹配，支持 ID 轮换；其它上传目录、普通共享 CDN 文件和其它 App 的 UA 保留。它不识别媒体内容，菜鸟内符合相同目录和格式的其它资源也会被拒绝。

Map Local 增加到五类：原有 `ads.index`、`ads.show`、`ads.mshow` 补可选 `.cn`；show/mshow 限定 `cn-acs.m` 或 `netflow-mtop` 两个已确认主机。新增 `cn-acs.m.cainiao.com` 的 `mtop.cainiao.adx.flyad.getad.cn`，继续返回空体 `404`。完整 API、主机和数值版本边界均保留。

页面清理逻辑仅升版本，没有改变字段删除策略。Surge 模块、双端脚本、脚本 URL、版本头和诊断版本同步构建。

QUIC 条件采用仓库既有的原生协议条件模式，但尚未在用户客户端验证对 draft-29 的识别。拒绝 QUIC也不保证所有请求都会回退；如果回退失败，目标主机上的普通业务请求也可能受影响。更新后需同时检查开屏与查件功能。

### QUIC 握手条件核对

以 PCAP 解析出的 SNI 和 `quic` 协议作为输入，读取实际 Surge/Egern 模块逐连接离线判断：24 条已识别连接中，旧版拒绝 0 条，新版拒绝 9 条，保留 15 条，两端差异为零。

九条连接属于上述五个需要改写的业务主机。其它 `gguser`、`caps`、`community`、`home-bff`、`nbfriend` 等主机没有加入 QUIC 拒绝范围。统计只代表规则条件覆盖，不能当作手机已经拒绝或已成功回退。

### 日志关联素材与 API 路径

日志关联的四个自营素材地址，旧规则匹配 **0/4**，新规则匹配 **4/4**。

16 条可定位的相关 Mtop 日志记录中，Map Local 路径覆盖 **1 → 9**；另七条属于原有页面清理路由。这是使用日志中的 URL 离线判断 TCP 回退后的匹配范围，不是实际观察到的拦截次数。

HAR 请求、QUIC 连接与应用日志记录不能相加。聚合记录见 [capture-audit-20261108-201845.json](capture-audit-20261108-201845.json)。原始 HAR、PCAP、视频、完整解压日志、Cookie、签名、账号、设备标识、IP 和定位信息未进入仓库。

## 手机验收

手动更新整个模块，确认 Surge 描述为 `1.2.0` 或 Egern 为 `eg-native-20261108-1.2.0`，并确认新增两个素材主机进入 MITM。完全退出后重新打开菜鸟，检查目标 QUIC 是否拒绝、广告 API 是否回退后命中 Map Local，以及视频和备用封面是否拒绝。

已有预取文件可能继续显示，模块不能删除 App 私有缓存。本次没有操作手机，也没有验证客户端对 draft-29 的识别、TCP 回退、查件业务或最终开屏效果。
