# 菜鸟小组件 1.2.3 手机反馈与 1.2.4 修复范围

日期：2026-11-09。使用用户提供的脱敏状态、合成复现及公开源码。没有读取手机凭据或私人 HAR，没有在电脑发个人接口、登录请求或执行上游代码。

## 手机已证实的结果

- 手机的固定合成 Cookie 发送对照中，`omit/include` 都收到测试标记，没有额外或重复 Cookie。它只证明该手机在固定回显服务的这两种请求能发送显式 Cookie，不证明淘宝网关接受个人会话。
- 当前保存来源为 `request_cookie`，首次直接 PDS 查询返回 `AUTH_REJECTED / FAIL_SYS_SESSION_EXPIRED / HTTP_200`。请求前缺 H5 token，响应没有更新 token，第一页及验证／token 轮次均为一。完整个人查询未成功，不能认定用户 App 已退出登录。
- 最近响应聚合记录属于公共时间或其它 MTOP，最近记录没有可用认证 Set-Cookie，也没有三个已知旧登录接口的结构行。聚合行保留最近结果，不能推导所有历史响应均没有 Cookie，更不能推导当前 iOS 不存在其它登录接口。

## 已复现的源码缺陷

旧实现只禁止公共时间建立 native／推断候选，却允许完整 Cookie 归为不受限的 `request_cookie`。独立合成六加三个场景、二十三个变体复现：这种公共请求可以替换受限候选、复活终止代次，甚至在另一账号保存失败后改回旧账号屏障，使旧账号再次发送 PDS。

1.2.4 将公共时间设为仅观察，保留同次明确身份冲突隔离。正常非公共新账号仍能保存和恢复，不把账号屏障泛化为禁止所有合法新采集。首次未确认的完整 Cookie 被拒绝时显示“App 接入未确认”，保留原 `expired`、原固定诊断与停止状态；已确认后失效仍保留原快照与时间。

这些是确证的来源／隔离修复。手机捕获时间与公共时间响应相邻，不能证明本次手机正由公共请求捕获；上述缺陷也不是本次 SESSION 拒绝的已证实根因。

## 请求合同没有找到新的漏参

当前 PDS 的 HTTPS 主机、API／1.0、appKey `12574478`、`jsv=2.7.4`、`originaljson/json`、UA／Referer、五十条页大小和 `needDynInfo`，均与既有固定公开 Kotlin／Python 来源一致。缺 token 拼 `undefined` 与已核验官方 MTOP 2.7.4 一致，不重复修已解决差异。

固定公开来源的独立查询登录产物来自淘宝 H5 登录／扫码确认及 HTTP 收尾 Cookie，不是打开 App 原生列表后平移 GW 字段。源码差异与手机根因是两种结论：来源实现一致不能证明手机会话被接受，缺 token 也不能单独证明 SESSION 的原因。

## 新公开登录证据及其限制

[官方 H5 登录前端 0.10.38](https://g.alicdn.com/vip/havana-nlogin/0.10.38/index.js)原地址 HTTP 200，共 722,601 字节，SHA-256：

```text
1603531d8fba5d11d7b7641c6f4f9c95b8a225b5ab37c28a27f91f2f918e4a92
```

约解码字符 250940 的 `taobaoNativeLogin`：非 iframe 且 MTOP 可用时调用强制 WindVane 的 `getUserSimple`；另一分支调用 `WindVane.call("aluWVJSBridge", "sdkLogin", ...)`。成功回调只完成 Promise，调用者跳向最终重定向地址。该函数没有提取 UID／Cookie，也没有自行执行 HTTP 登录收尾；不能推断 App 桥内部是否注入 H5 Cookie。约 406480／406820 的普通网页登录分支另有 `asyncUrls/miniLogouts/miniVsts` HTTP 收尾，不是 native 成功分支的必经证明。

[固定 cddjr/check 源码](https://github.com/cddjr/check/blob/8bfb8cd12fe2b8988c35bfbdbdc030f7f357407a/ck_hema_town.py)最后改动于 2024-05-02。256–265、882–915 行表明旧 `com.taobao.mtop.mLoginUnitService.autoLogin` 的服务端 Cookie 可以位于 `$.data.returnValue.data` JSON 字符串解析后的 `cookies:string[]`，而非 Set-Cookie。但主动请求需要已有 `user_id/token/umidToken/wua` 和盒马上下文，当前 Cookie 无法导出这些前置值。手机没有观察到该旧接口；仅加正文解析不会产生会话，也不能保证当前 iOS 及 Cookie 域路径。

[官方 iOS 接入文档](https://developer.alibaba.com/docs/doc.htm?treeId=713&articleId=118399&docType=1)仍要求原生 SDK、安全图片、应用 scheme 和授权回调。[Egern API](https://egernapp.com/zh-CN/docs/javascript-api/)没有在菜鸟／淘宝进程调用 WindVane、SDK 登录或安全组件的接口。HTTP 代理模块不是 App 沙盒内的登录桥。

[PickTool 固定源码](https://github.com/yimeifun/PickTool/tree/a52d780717fb8250487795b0e2fc5d14db47e2b2)提供淘宝 App 内网页导航的 `tbopen/h5Url` 入口，但只负责打开 App，不读账号、不做网络或后台查询。它不能证明 Cookie 注入或当前 iOS 的可复用会话；不把打开 App 的工具当独立刷新的实现。

## 本次不做的猜测修改

没有 Cookie 必需性证据，不扩展 `havana_*` 等未知登录字段；没有现代登录 API 的核验结果，不扩大任意 MTOP 正文采集。也不盲加公共 token bootstrap、换网关、复制一次性 native 签名、接入第三方签名服务或用 App 响应缓存冒充新查询。

当前仍没有核验出可从这次 iOS App 捕获到的确定 H5 会话／兑换。独立更新目标尚未完成。用户不必再重复原手机操作；后续只有真正可复用的服务端登录产物与手机完整个人查询，才能确认接通。
