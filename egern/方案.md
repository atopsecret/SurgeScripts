# Egern 原生模块与配置迁移

## 目标与边界

把现有七个主模块分别实现为 Egern 原生 YAML 与 JavaScript：高德、京东、闲鱼、拼多多、红果、戒烟军团、蔚来。旧 Surge 文件不改、不删。Discord 不恢复；用户已删除的根 `tests/`、`recovery/` 不恢复。

以当前 Surge `anynook` 为路由与节点事实来源，新建私人 Egern 配置。现有 Egern 配置仅用于保留其证书和必要的客户端差异，不以旧账号链接或已删除备份作为路由来源。私人节点、证书、控制服务地址和局域网名称不得进入公开仓库。

初始准备阶段只在独立本地工作树中生成文件，不发布或替换现用配置。后续公开推送与 iCloud 文件替换已按确认执行，结果见文末；证书信任、Tailscale 连通和真实签到不作为本次已完成的验收项。

## 已核实的接口

- [原生脚本 API](https://egernapp.com/zh-CN/docs/javascript-api/)：使用 `export default async function(ctx)`；请求与响应正文为一次性流；已读取正文后解析或处理失败，必须显式返回保存的原文。
- [脚本配置](https://egernapp.com/docs/configuration/scriptings/)：使用 `http_request`、`http_response`、`schedule`、`generic`；定时字段是 `cron`，不是 Surge 的 `cronexp`。`ctx.http` 超时为毫秒，YAML 脚本超时为秒。
- [模块配置](https://egernapp.com/docs/configuration/modules/)：原生 YAML；模块不携带用户 CA、Token 或节点。主配置用 `modules[].url` 引用。
- [规则配置](https://egernapp.com/docs/configuration/rules/)：`and.match` 可组合 `url_regex`、`user_agent` 和 `protocol`；协议值用小写 `quic`。远程规则采用无策略的原生 `domain_set`、`domain_suffix_set`、`ip_cidr_set` 等集合，策略在主配置的 `rule_set` 引用处指定。
- [主配置示例](https://egernapp.com/docs/configuration/example/)：策略使用 `policy_groups`；证书字段为 `mitm.ca_p12`、`mitm.ca_passphrase`；解密域名用 `hostnames.includes`。

## 新版与不等价项

Apple 官方公开接口于本次检查返回 [Egern 2.21.0](https://itunes.apple.com/lookup?id=1616105820&country=us)，发布时间为 2026-11-04，最低 iOS 16。该版说明明确新增独立 Tailscale/Headscale 节点、浏览器或认证密钥登录、IPv4/IPv6、出口节点、子网路由和 MagicDNS。

当前官网 `proxies`、完整配置示例和公开快速入门仍未提供新 Tailscale 节点的 YAML 字段。因此只接受 Egern 2.21 实际导出的原生节点，不把 Surge `interactive-login`、`control-url` 或状态文件猜译成新字段。自建 Headscale 还需要从原生设置和导出差异核验控制字段及原地址；认证密钥或任意非凭据 URL 不能代替控制字段证据。在原生节点和控制端核验完成前，私人草稿明确标记 `pending-tailnet`，把已有 Tailnet 规则导向只含 `REJECT` 的策略组；这不是已完成的组网配置，也不替换使用中的文件。

[Tailscale 认证密钥文档](https://tailscale.com/kb/1085/auth-keys)明确每个新节点登录时生成自己的节点密钥；不复制 Surge 节点密钥/state，不声称同名 hostname 保持原设备身份。旧节点保留到新客户端实际连通后。

[Egern 条件策略](https://egernapp.com/docs/configuration/policy_groups/#conditional-selection)只公开 SSID、BSSID、蜂窝制式三类条件，没有网关条件。NAS 保留为手动 `select`，列表顺序是 `NAS-Relay`、`DIRECT`，不写不存在的 `default_policy`，不宣称原 `ROUTER` 自动切换已复刻或设备选择状态已设置。

[DNS 文档](https://egernapp.com/docs/configuration/dns/)确认 `dns.hosts` 处理静态/别名，`dns.forward` 处理指定服务器。保留当前 Surge 的 DNS 上游与两条私人转发，不复制会绕过 Forward 的旧 Egern `proxy_nameservers`。主配置 DNS 劫持用已文档化 `['*']`；这是与 Surge 只劫持两个 DNS 地址的显式差异。

Hysteria2 的 Egern `bandwidth` 仅表示上传，不能把 Surge 下载带宽误填为上传带宽。Surge 控制面板/API、`read-etc-hosts`、`extended-matching`、`FINAL,dns-failed`、MITM 跳过上游证书验证没有已确认的等价字段，转换说明逐项列明而不是照抄。

## 模块行为

1. **高德**：精确保留 RT 开屏 multipart 字节、边界和响应头；旧 JSON 开屏返回成功空列表。页面净化仅匹配既有接口，不拦地图主域或普通图片 CDN。保留本地诊断，默认无通知。
2. **京东**：保留八类接口，导航列表不因陌生结构被清空；开屏只剥广告字段，不返回整个空对象。查询参数顺序可变；普通商品图不匹配专用开屏尺寸。未知接口、HTTP 错误和无效 JSON 放行。
3. **闲鱼**：覆盖六个网关、新旧开屏及 `cacheAd`；服务端 `ret` 错误保持不变。不把广告上报伪装为新的登录成功响应。默认静默，诊断可手动运行。
4. **拼多多**：原生逻辑规则保留裸 IP 素材加 UA 的双条件以及单域 QUIC 条件，不扩大到整域或全局阻断。路径分发必须另验域名或精确 Host 归属。保留商品评价图片和未知导航结构。
5. **红果**：保留原广告与插播主机范围，不解密整个 `snssdk.com`。不搬默认拒绝公共 DNS 服务的两条规则，避免与用户主 DNS 产生冲突；在使用说明中明示差异。
6. **戒烟军团**：只在已知 `webservice510.asmx` 响应中改写原有客户端标志，不新增认证接口、服务端权限或存储。
7. **蔚来**：按原有已知业务路径捕获请求头，凭据只写 Egern 本地存储。定时 09:00；原生 `ctx.http`、存储和通知。保留凭据变动终止、403 不作废凭据、真正失效才要求重新登录；原 2.1.2 只有单执行防重复结束，原生版新增每日确认成功后去重和到期锁。`ctx.storage` 没有 CAS/事务保证，不声称跨进程绝对互斥。不自动迁移 Surge 存储，也不在测试中发送真实签到。

每个脚本自包含，不引入远程公共运行时或 Surge 全局变量适配器。保留作者与来源。测试只用虚构数据和内存存储。

## 私人配置与远程规则

保留五个策略组 `Proxy`、`Apple`、`Intelligence`、`Binance`、`NAS`；不恢复 Telegram、YouTube、GlobalMedia 独立组。保留私人例外顺序、Host、真实 IP 例外、排除路由、国内直连与最终 Proxy。

六份公共 `.list` 不变；在 `Rules` 工作树下新增独立 Egern 原生集合，逐条转换、去重结果必须与当前静态正文等价，许可与来源说明保留。另加 `LAN.yaml`、`LAN-no-resolve.yaml`，显式保留两条原内置 LAN 引用的相同 14 条条件及不同解析选项；Tailnet 必须位于 LAN 前。不启用 GitHub Actions、搜索程序或定时抓取。

准备阶段先新建权限 `0600` 的私人配置，不覆盖原文件；用户确认后，备份并更新 iCloud 的 Egern 配置，Surge anynook 保持不变。Egern 自己的 CA 保留，Tailscale 登录状态不跨客户端拷贝。原配置不能精确映射的项逐条记录真实替代方式，不用无效字段凑齐。

## 验证标准

- 七个原生 YAML 的字段、正则、远程脚本路径、本地文件存在性与索引一致。
- 每个脚本通过原生上下文单元测试：目标改写、非目标透传、错误响应、无效正文、存储不可用、正文单次消费和幂等。
- 保留既有高德与蔚来测试；不以 Surge 检查代替 Egern 检查。
- 六份原生集合与 `.list` 正文条件、数量及许可对应。
- 私人配置可解析，所有策略/节点引用闭合，远程规则与模块只指向当前账号；Tailscale 路由先于兜底。
- 公开差异无凭据、私有 CA、私人主配置、旧账号链接、Discord、工作流或自动搜索工具。
- 没有本地 Egern 应用或官方可调用验证器时，只报告静态与模拟测试，不声称手机导入、证书信任、Tailscale 登录或真实 App 验收通过。
