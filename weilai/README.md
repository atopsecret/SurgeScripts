# 蔚来自动签到

Surge **3.2.1** 与 Egern **3.2.0** 分别使用本目录的原始安装入口。Surge 的完整凭据捕获、统计观察、09:00 定时签到和只读诊断共用 [canonical 脚本](<weilai-auto-checkin.js>)；[Egern 原生脚本](<weilai-auto-checkin.egern.js>)及 [YAML 模块](<weilai-auto-checkin.egern.yaml>)保持原 3.2.0 实现，不混用客户端 API 或凭据。

## Surge 安装与更新

安装入口仍是原功能目录的 [Surge 模块](<weilai-auto-checkin.sgmodule>)：

```text
https://raw.githubusercontent.com/atopsecret/SurgeScripts/main/weilai/weilai-auto-checkin.sgmodule?v=3.2.1
```

1. Surge iOS 6.0+ 导入模块，开启 MITM，并安装、信任当前 Surge CA。解密仅追加 `gateway-front-external.nio.com`、`app.nio.com`、`api.nio.com`。macOS 使用相同 Surge API，本文离线回归不等于 macOS 或锁屏调度验收。
2. 模块与 [手动配置](<weilai-surge-config.conf>)二选一；不要同时保留旧 installed 模块、主配置内联的旧蔚来脚本和新版模块。相同请求入口位于新模块之前时，旧入口可能先处理凭据，新版诊断仍显示“尚未捕获”。
3. 更新模块、重新载入配置，并刷新四个远程脚本缓存；四项地址均是下面同一条 `main` + 版本 URL。不必重建额外安装目录。
4. 在当前 Surge 下重新打开已登录的蔚来 App 签到或个人页面。首次新凭据会显示“凭据已更新”；相同 Token 与 UA 不重复写入或提醒，更新后以本地诊断中的版本及捕获结果码为准。
5. 运行“蔚来本地诊断”，确认 `Surge 原生脚本 3.2.1` 和“已捕获”。需要立即验证时手动运行唯一的“蔚来自动签到”定时任务；generic 不是签到入口。

四入口的脚本地址：

```text
https://raw.githubusercontent.com/atopsecret/SurgeScripts/main/weilai/weilai-auto-checkin.js?v=3.2.1
```

| 原模块入口 | 类型 | 引擎 / 上限 | 行为 |
| --- | --- | --- | --- |
| 蔚来Token抓取 | http-request | JSC / 10 秒 | 只读取已知业务请求头，`requires-body=false` |
| 蔚来统计观察 | http-response | JSC / 5 秒 | 既有签到端点的原字节观察，`binary-body-mode=true`、262,144 字节上限 |
| 蔚来自动签到 | cron | WebView / 30 秒 | 唯一 `0 9 * * *` 定时项，`wake-system=1` |
| 蔚来本地诊断 | generic | JSC / 10 秒 | 只读本地状态，不写存储、不发通知、不发送签到 |

cron 使用 Surge 设备时区；每日确认与观察记录按蔚来中国业务的 UTC+8 日界判断。

## 通知、统计与受控复查

成功通知：

```text
蔚来签到
签到成功 ✅
🔥 连续签到：564 天
📊 累计签到：570 天
```

已有当日完整确认时显示“今日已签到 ✅”，不发请求。缺失统计保留“未知”，不靠本地运行次数累计，也不把昨日累计加一。成功日志使用“今日签到已确认”，因为 `checked_in=true` 不区分本次首次签到和此前已签到，不宣称本次获得奖励。

Surge 保留完整 3.2.0 状态机的“先确认、后补统计、再通知”顺序：

1. 正常 HTTP 200、`result_code=success`、data 对象且 `checked_in === true` 后，先严格回读验证当日成功记录和已取得的统计，不提前发送成功通知。
2. 先补用同日、同代凭据的真实观察数字；累计仍缺失时，向原固定签到端点追加**最多一次** `event=checkin` POST。旧版 `fetchCheckinStats()` 实际也是此 POST，不是只读 GET；没有新增猜测的查询路径。
3. 复查返回后再次读取同日观察，只补缺项，保留首次连续天数及合法零值；新补累计不得小于已知连续数。将可用结果保存后统一发一条通知。

首个成功未确认保存时，不进入统计复查；仍如实报告服务器确认，并说明本地防重复未保存。复查失败、401/429、超时或解析失败不重试、不作废有效凭据、不丢已保存的签到成功。复查和首次请求共用 24 秒预算，复查不重置预算；账号、锁或 UTC+8 日界变化后停止旧任务。

当日旧成功记录缺累计时，手动运行定时任务可仅走一次复查。取得完整统计后，当天再运行没有请求。复查期间持有原任务锁，重入任务保持静默，通知由持锁任务统一发出。

### 累计解析不猜字段

只接受非负安全整数，或转换后符合相同条件的 1–16 位纯数字字符串；空白、指数、小数、布尔、对象和任意文本均不进入统计。字段优先级不变：

- 连续：`stats.continuous_checkin_days`、`stats.continuous_days`，然后顶层同名字段。
- 累计：`stats.accumulate_days`、顶层 `accumulate_days`，再读 `stats` 与顶层 `accumulateDays` / `total_days`，最后 `award_info.accumulate_days` / `award_info.total_days`。
- 合法零值仍优先；观察和复查只补缺值，不覆盖已有合法数字。

3.2.1 只修复一个已在离线 mock 复现的诊断保存缺口：复查业务确认成功、统计数字未变但固定 `fields/types` 有变化时，也保存这组元数据。保留 `confirmedAt`、`day`、`generation`、锁归属、数值解析与 POST 次数；不增加统计 aliases 或放宽观察范围。新响应的 `missing` 不覆盖既有非缺失类型。

该修复解决“新字段类型未留在本地诊断”问题，**不证明它是手机累计天数缺失的根因**，也不把无效累计字段转换成一个猜测天数。

## 被动统计观察

仅现有固定签到端点的 GET/POST、HTTP 200、业务成功且 `checked_in === true` 被观察。请求 Authorization 必须仍属于当前有效凭据与同一 `generation`；写入前再次检查凭据及日界。昨日、未来时间或另一代观察不用于今天。

正文完整读取一次后显式回传原字节；解析、字符集、超尺寸或存储故障不改写原响应，不二次读取，不额外请求，不写签到任务 journal 或锁。允许 UTF-8/UTF8/US-ASCII 与未声明编码；其他字符集直接保持原响应。没有独立的正文超时 Promise 竞速，正文大小和原生执行上限由模块控制。

独立观察记录只能补用真实的同日数字，不冒充任务已签到。可选观察缓存或字段元数据损坏只降级诊断，不丢已确认签到或有效凭据。

## Surge 凭据、去重与任务锁

路径归回原目录不改变 3.x 已测试的 `ios_nio_v3_*` 存储键，因此已有新命名空间状态无需清空：

| Key | 内容 |
| --- | --- |
| `ios_nio_v3_auth_state_v1` | Token、观察时间、失效标记、合法 UA 与凭据代号 |
| `ios_nio_v3_checkin_v1` | 30 秒任务租约、UTC+8 当日成功、校验后的统计与可选固定字段类型 |
| `ios_nio_v3_statistics_v1` | 同日、同代真实观察的统计与固定字段类型，不保存 Token |
| `ios_nio_v3_capture_notice_v1` | 30 秒合并提醒的时间戳 |
| `ios_nio_v3_capture_status_v1` | 固定捕获结果码、时间与执行版本 |

不读取、搬运或删除旧 Surge `weilai_auth_state_v1` / `weilai_auth_token` / `weilai_token_last_update` 或 Egern 凭据。仅有旧键的安装需在当前客户端重新捕获。新 Token 换代；同 Token 保留失效标记与代号；同 Token 同 UA 不重写观察时间。保存超过 30 天不推断服务端已过期。

必要存储均严格回读确认。核心状态损坏、存储不可用或加锁未确认时不发 POST；真实目标请求可修复损坏的凭据状态，损坏 journal 不自动删除或当作空记录。

同代在 UTC+8 当日已经确认且统计完整时不再发送签到；累计缺失仅走上述最多一次复查。凭据换代不沿用旧代成功。进入任务、真正 POST 前、回调/正文返回后及 429 等待后重新检查 Token、代号、失效标记和锁。只释放自己持有的锁；没有 CAS/事务保证，不声称跨执行器绝对只提交一次。

网络、超时、5xx、未知 JSON 或业务结果不记成功，保留短租约防立即重复提交。租约到期不代表服务端未处理先前请求。

## 请求与失败处理

- 原固定端点、`event=checkin` 表单、秒级 timestamp；单次 timeout 5 秒。适配器将内部毫秒精确转换为 Surge 秒，并关闭自动跳转、自动 Cookie 和宽松 TLS。
- 首次签到只对明确 HTTP 429 有限重试，严格整数秒或标准 HTTP 日期，至少等 1 秒、最多三次，受统一 24 秒预算约束；统计复查不重试。
- HTTP 401 或 HTTP 200/403 的明确认证错误码才标记当前凭据失效；普通 403 与 5xx 不作废。旧账号迟到结果不污染新代凭据或今日记录。
- 不输出完整 URL、Token、任意异常、服务端原文或整包响应；只记录固定文案、结果码、已校验数字及有限字段类型。持久化凭据仍包含登录 Token，请勿分享存储内容。
- 凭据捕获结果码：`C-SAVED`、`C-UNCHANGED`、`C-COALESCED`、`C-SUPERSEDED`；异常分为 `E-READ`、`E-WRITE`、`E-READBACK`、`E-EMPTY`、`E-FORMAT`、`E-MISMATCH`。可选诊断/提醒故障不回滚有效凭据。

## Egern 原生版 3.2.0

安装地址：

```text
https://raw.githubusercontent.com/atopsecret/SurgeScripts/main/weilai/weilai-auto-checkin.egern.yaml?v=3.2.0
```

1. 导入原生 YAML，并安装、信任 Egern 当前 CA。解密只追加三个既有蔚来主机与已知业务路径，不扩到车辆控制域名。
2. 在 Egern 下重新打开已登录的蔚来 App 的签到或个人页面。请求脚本只读取 Authorization 与 UA，不读 body、不签到；新凭据保存后发简短无声提醒，30 秒内不重复提醒，同 Token 同 UA 不重写凭据。
3. `蔚来自动签到 · Egern` 是 `schedule`，cron 为 `0 9 * * *`。需要立即执行时手动运行这条定时任务；不是运行 generic，也不使用伪造域名。
4. `蔚来本地诊断 · Egern` 是 generic，只读本地状态，返回合法 widget 并写日志；不发通知、不发送签到、不显示 Token。
5. `蔚来统计观察 · Egern` 是 response 钩子，只读取现有固定签到端点的成功响应。它不发送请求、不重新抓取凭据、不修改响应内容，也不写签到任务锁。

3.0.1 把必要存储改为 `ctx.storage.set()` / `get()` 原始字符串回读，避免 `setJSON()` / `getJSON()` 的对象键顺序差异。3.1.3 进一步修复捕获入口的误报：字段等价的回读可确认，更新的同凭据快照可合并；回读是其它新凭据或失效状态时，让旧捕获退出，不回写旧快照、不报告本次成功。写入前后仍停留在原快照、状态缺失、格式损坏或 API 异常时，明确报告失败，不盲目重试。

同 Token 同 UA 没有需要更新的业务内容，3.1.3 不再因每个 App 请求重写 `observedAt`。该时间从未用于推断服务端 Token 过期；同凭据的失效标记、`generation` 和当日确认仍保留。任务锁、失效标记及签到确认的严格写入校验没有放宽。

捕获脚本日志现在包含实际执行版本和固定结果码。可选 `weilai_egern_capture_status_v1` 只存版本、记录时间和结果码；本地诊断会显示该记录，以及可用时的 Egern App 版本。诊断记录故障不作废凭据、签到记录或统计。更新后先打开 App，再运行诊断，区分历史通知和新捕获结果：

- `C-SAVED`：已核验保存。
- `C-UNCHANGED`：凭据及 UA 未变，无需重写。
- `C-COALESCED`：已有更新的同凭据快照，保留它。
- `C-SUPERSEDED`：其它请求已更新当前状态，旧捕获退出。
- `E-READ` / `E-WRITE` / `E-READBACK`：分别是捕获前读取、写入、写后读取 API 异常。
- `E-EMPTY` / `E-FORMAT` / `E-MISMATCH`：分别是写后缺失、格式异常、未匹配到本次更新。

这些码不包含 Token、账号、请求 URL、响应正文或异常原文。保存失败通知只给出结果码与本地诊断入口，不再将所有错误写成“本地写入未确认”。现有凭据键、提醒键、统计键和任务记录键均不变，不需要清空存储或重复签到。

捕获、统计观察、定时与诊断四个入口使用同一个已核验的完整提交地址，避免 GitHub Raw 的 `main` 缓存或客户端旧脚本缓存。模块本身仍可跟随 `main` 更新。重新载入配置并更新模块后，运行“蔚来本地诊断”确认显示 `Egern 原生脚本 3.2.0`；仅打开 App 不保证模块与脚本缓存已经更新。相同凭据捕获会保持静默，以本地诊断的“已捕获”及新版捕获记录为准。

3.1.1 的提醒时间单独保存在 `weilai_egern_capture_notice_v1`，只存时间戳，不含 Token 或账号代号。提醒记录损坏时重新记录；提醒读写或通知 API 失败不回滚凭据，也不影响签到任务。合并仅针对共享存储中可观察的连续更新；原生存储没有 CAS，不能保证完全并发的不同执行器绝不重复提醒。

### 当日累计统计与被动观察

3.1.0 补回旧版累计字段兼容，并增加独立观察记录 `weilai_egern_statistics_v1`。只有现有签到端点、HTTP 200、业务成功、`checked_in === true`，且请求凭据仍属于当前有效 `generation` 时才保存校验后的统计数字与固定字段类型。写入前重新核对凭据和 UTC+8 日界；不同代、昨日或未来的观察不用于今日统计。

观察记录不写 Token，不覆盖 `weilai_egern_checkin_v1` 的今日确认或任务锁。当日签到已确认但累计缺失时，诊断、定时任务和去重通知可以补用同日、同代的真实观察值；已有合法数字和零值仍优先。没有累计值就保持“未知”，不会把昨日累计加一。

新签到记录保存可选字段类型，累计缺失时可直接从本地诊断查看，不必寻找运行日志。旧记录未保存这项元数据时仍可使用；可选字段类型损坏只降级诊断，不使有效的签到确认失效。

更新后可以运行本地诊断查看现有统计。今天已经确认签到、但累计仍缺失时，可手动运行一次定时任务执行下述复查。打开 App 是否产生观察响应、响应是否带累计数，仍取决于 App 与服务器。

### 3.2.0 先补统计，再通知

1. 首次签到确认后，先保存当日成功和已取得的统计，不立即发送成功通知。
2. 重新读取同日、同代的观察记录；若累计仍缺失，向同一签到端点追加一次 `event=checkin` POST，沿用当前凭据和 UA。它是旧版补统计操作的受控恢复，不是读取控制台日志或只读 GET。
3. 复查返回后再读一次观察记录，只补缺失数字；保留首次连续天数和合法零值。新增累计必须不小于已知连续数。补齐结果保存到原签到记录，最后发送一条通知。

累计已有值时不追加请求。复查每次运行最多一次，不重试 429、超时、网络或业务错误；失败不作废凭据、不丢失已保存的签到成功，也不把未知累计猜成昨天加一。首个确认记录未保存成功时不进入复查。

当天旧记录缺累计时，手动执行定时任务可以只走复查分支；取得完整统计后，当天再运行无需发请求。复查期间持有原任务锁，重入任务保持静默，通知由持锁任务统一发出。账号变化、锁被接管或跨日时停止，不合并旧上下文结果。

观察入口 `body_required: true`、正文上限 262,144 字节、原生执行上限 5 秒。正文只读取一次；完整取得后，无论解析或本地保存是否成功，都显式回传原字节，不修改状态码或响应头。没有额外的 Promise 正文超时竞速，以免读取尚未取消却提前丢失原字节回传。流读取失败或原生执行超时后的处理由 Egern 控制，离线检查不能证明客户端内部缓冲行为。

定时采用 Egern 的设备时区。官方文档没有 Surge `wake-system` 的等价字段，本模块不写该字段，也不承诺锁屏调度完全相同。

### 凭据、幂等与任务锁

凭据只在 `weilai_egern_auth_state_v1` 保存，包含 Token、观察时间、失效标记、合法 UA 和 `generation`。新 Token 换一代，同 Token 保留失效标记与代号；同 Token 同 UA 不反复更新时间。A→B→A 也不会误认成原来的在途任务。不读 `weilai_auth_state_v1` 或其他旧 Surge 键。

任务记录 `weilai_egern_checkin_v1` 只存任务 ID、代号、锁时间、已确认日期/有限统计及可选字段类型，不重复存 Token。所有必要存储写入都回读确认；核心状态不可读、结构不符或加锁未确认时不发 POST。真实目标请求可修复损坏的凭据状态；损坏任务记录不自动删掉或当作空记录。可选观察缓存或诊断元数据故障不作废凭据、不删除有效确认记录。

**每日成功去重与到期锁是 Egern 3.0.0 新增，不是旧 Surge 2.1.2 已有能力。** 仅 HTTP 200、`result_code: success`、data 对象且 `checked_in === true` 才记成功。同代凭据在 UTC+8 当日已确认后，不再进入首次签到重试循环；3.2.0 仅在缺累计时允许上述一次同接口 POST 复查。新代凭据不沿用旧代标记；没有可靠账号 ID，因此不声称同一服务端账号更换 Token 后仍严格按账号去重。

任务锁 30 秒到期。进入任务、真正调用 POST 前、响应与 body 返回后以及 429 等待后都重新校验凭据代号、失效标记和锁归属；变化后停止，不改用新账号继续旧任务。只释放自己持有的锁。网络、超时或解析结果未知时不标成功，保留短租约以防马上重复执行；到期不代表服务器没有处理过请求。

Egern `ctx.storage` 没有文档化的 CAS、事务或跨进程互斥保证。短同步读写与回读能防常见重入，不能证明跨执行器同时启动时绝对只提交一次。测试覆盖同上下文的重入和可观察的状态变化，不能替代实际客户端的存储作用域、持久化与并发验证。

### 请求和失败处理

- 原生 `ctx.http.post` 使用原有固定端点、`event=checkin` 表单与秒级时间戳；`timeout: 5000` 为毫秒，`redirect: manual`、`credentials: omit`、`insecureTls: false`。不自动带 Cookie 或沿跳转把 Authorization 发给其他主机。
- 每次请求与响应 body 读取共用至多 5 秒，首次签到和统计复查共用整个任务的 24 秒预算，YAML 上限 30 秒。复查不重置预算，预留最终处理时间；时间不足时不追加。首次签到仍仅对明确 429 最多提交三次，另有最多一次统计复查。Promise 兜底限制异常挂起；没有文档化 AbortSignal，不能说兜底超时已经取消服务端收到的 POST。
- 只有明确 429 按严格整数秒或标准 HTTP 日期等待，至少 1 秒、最多 3 次，并受同一总预算限制。网络失败、5xx、跳转、未知 JSON/业务状态不自动重发。
- 401 或 200/403 的明确认证码才标记失效。普通 403 不作废；5xx 即使夹带认证字样也不作废。迟到旧响应不写新代凭据或新代今日记录。
- 确认成功但每日记录未确认保存时，仍如实报告服务器确认结果，并明示本地防重复未保存，不追加统计请求。统计字段与 Surge 版一致；纯数字字符串转换后，任务记录只保存规范化的数字。当日真实观察和复查响应只能补缺失项；仍缺失时显示“未知”。
- 日志和通知仅本地固定文案及校验后的数字，不输出 URL、Token、任意异常或服务端原文；不宣称本次获得了新奖励。
