# 菜鸟取件小组件 1.3.1 手机接入

**1.3.1 已发布。手机实际连接尚未验收。** 实现提交 `448f0d0` 于 2026-11-09 17:18:38 完成十四个公开原地址逐字节回读。手机模块及 JS 已更新，但随后出现新官方 RPC 时仍未接通；现已复现旧 H5 隔离标记阻挡首次迁移的问题，后续见 [1.3.2 接入说明](开始使用-1.3.2.md)。以下保留本版原接入范围。

本版修复“官方组件已有 token、没有再次签发时无法接入”的限制。合法的实际查询可以直接建立凭据候选，不要求先捕获带 UID 的签发响应。候选不等于查询成功，也不表示已核实账号 UID。

## 已安装用户

1. 更新原“菜鸟取件 · 原生小组件”远程模块及它引用的 JS，确认模块描述和 JS 首行都显示 **1.3.1**。保持 `CONNECTION_MODE=auto`，手动 Cookie 留空。不要同时启用两份同名模块；已有自己的 Egern CA 不用重装。
2. 保留主屏已有的 **菜鸟 App 自带的小组件**，等待它实际刷新一次。无需删除重装、退出重登或重复旧 Cookie 试验。尚未添加官方组件时先添加一个，正常打开本人菜鸟 App 一次，再等它刷新。
3. 回到 Egern 的小组件画廊，运行 **“菜鸟取件”**。实际 token 与合法模板已捕获时，本组件会发送带新时间戳的新 POST；缺失或结构不符时明确停止，不借用其它请求的参数，不猜 Android 设备值。
4. 第一次独立查询成功后，关闭菜鸟 App，再运行“菜鸟取件”一次。第二次新请求仍成功，才确认本手机能在 App 关闭时独立查摘要。后续系统刷新时机由 iOS 决定。

不需要电脑、HAR、复制凭据、退出重登或另装诊断。“菜鸟连接状态”属于同一模块，只显示采集阶段、固定错误和新查询次数，不显示 token、账号或包裹正文。如果还未接通，反馈这里的文字即可，不反复重做上述操作。

## 已确认的现场事实

2026-11-09，本人 iPhone 第三个主屏页面已有官方小号组件。北京时间 16:45:16，Egern 记录到官方 `WidgetExtension` 向 `guoguouser.cainiao.com` 的精确 `WidgetLogisticsService/1.0.0/queryWidgetDetailsV2` 端点发送 POST，使用 `Http-Rpc-Type: JsonContent`，HTTP 状态为 200；现有 MITM 已命中。

此次仅查看连接元数据和请求头，没有读取该次正文或凭据。HTTP 200 不代表业务成功，也没有确认 iOS 的 JSON 字段或结果结构。16:47 的 1.3.0 连接状态仍无官方专用会话。旧版必须先看到签发记录，即使实际查询已经出现也可能无法接入；1.3.1 修复的是这一已复现的本地限制。

## 仍须分别验收

- **实际候选被接受**：只说明取得符合已知合同的 token 和模板。RPC-only 路径用 token 摘要隔离 bearer 凭据，不把它当成已核实 UID；原签发与 UID 路径仍保留。
- **本组件首次独立查询成功**：必须由本组件发新 POST，并接受本次合法结果。不能复制官方 App 的包裹响应来冒充更新。
- **关闭 App 后第二次新查询成功**：这是单独的手机验收项，不能用代码发布或离线测试代替。
- **完整列表与取件码**：当前专用接口只接入官方待取摘要，没有已确认的全量分页或结构化取件码合同。不从描述中的数字猜码，锁屏默认隐藏整段取件摘要。

新 token 建新代次，清空旧摘要、确认及成功次数；被替换的旧 token 不能靠迟到流量恢复。`INVALID_TOKEN` 停止同值重试，Egern 不自行执行菜鸟原生续期。明确身份冲突、退出或存储不确定时仍停止，不退回旧账号查询。

iOS 正文尚未确认。若实际请求不符合现有 JSON RPC 模板，本组件会停在未接通；不能靠重复添加官方组件消除这个差异。Android 研究事实与范围见[官方协议核对](官方小组件协议核对.md)，本版接入方式见 [README](README.md)。
