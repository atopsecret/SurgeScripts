# 蔚来自动签到

Surge 脚本 2.1.6。请求钩子保存已知蔚来业务接口中的 Bearer 凭据，定时任务每天 09:00 使用它签到。手动运行任务仅用于立即验证，不是每日操作要求；旧的网页触发入口已移除。

另提供独立 [Egern 原生模块](weilai-auto-checkin.egern.yaml)与[脚本](weilai-auto-checkin.egern.js) 3.1.3。它不使用 Surge 全局，也不自动搬运 Surge 凭据。下节先说明 Surge；Egern 的当日统计观察与防重复边界见后文。

## 安装与依赖

- [模块](weilai-auto-checkin.sgmodule)和[手动配置](weilai-surge-config.conf)二选一，不重复启用。
- 使用 Surge iOS 5.9.0 / Mac 5.5.0 或更高版本；关闭请求跳转和自动 Cookie 等选项依赖该版本起提供的接口。Egern 使用独立 YAML，不能套用这些 Surge 版本要求。
- 从本仓库更新模块后，也要刷新远程脚本缓存。任务日志首行应显示 `脚本版本 2.1.6`。本地测试时，可将两处 `script-path` 都改为客户端内的新版脚本文件。
- 开启 MITM，并安装、信任 Surge 当前 CA。抓取范围仅限配置中的三个主机和已知业务路径。
- 打开已登录的蔚来 App 的签到或个人页面，看到凭据更新通知后运行任务。没有通知也可能只是凭据未变化。

## 日志与通知

凭据更新通知只显示“凭据已更新”，没有正文。Egern 将 30 秒内的多次凭据变化合并为一次提醒；Token 与 UA 都没变化时不重复写凭据，也不重复提醒。新 Token 或有效 UA 变化仍会保存。

成功通知示例：

```text
蔚来签到
签到成功 ✅
🔥 连续签到：564 天
📊 累计签到：570 天
```

Egern 已有当日本地成功记录时，通知显示“今日已签到 ✅”，不再重复提交。这里只改通知展示，日志和诊断保留原格式。

成功日志和通知都显示连续签到及累计天数；字段缺失时显示“未知”，日志只列出已知统计字段的类型，不输出字段原文。失败说明也同步写入日志，即使通知不可用，仍能看到原因。日志首行标明实际执行版本，方便识别缓存中的旧脚本。

## 行为与边界

签到使用抓包验证过的 POST 路径、`event=checkin` 表单和秒级时间戳。返回正常 HTTP、业务成功和 `checked_in=true` 时，通知显示“签到成功 ✅”，日志记录“今日签到已确认”。该响应无法区分本次首次签到和此前已签到，不宣称本次获得奖励。

统计接受响应中的非负安全整数，或转换后满足同一条件的 1–16 位纯数字字符串；拒绝空白、指数、小数、布尔值和任意文本。连续天数先读 `stats.continuous_checkin_days`、`stats.continuous_days`，再读顶层同名字段。累计保留 `stats.accumulate_days`、顶层 `accumulate_days` 的优先级，再读 `stats` 和顶层的 `accumulateDays` / `total_days`，以及 `award_info.accumulate_days` / `award_info.total_days`；合法零值不会被后面的别名覆盖。缺失项显示“未知”，不靠本地运行天数累加，也不为补统计再次签到。

旧版名为 `fetchCheckinStats()` 的补统计操作实际仍是签到 POST，不是只读查询。当前版本不恢复这次重复提交，也不添加没有累计字段契约的查询端点。

每次请求超时 5 秒，任务预算 24 秒；只有明确的 HTTP 429 限流响应才会按重试时间有限重试，最多提交三次。网络异常、超时、5xx、解析错误或业务失败不盲目重发 POST，因为服务端可能已经完成签到。

凭据保存在客户端本地 `weilai_auth_state_v1`，兼容读取旧的 `weilai_auth_token` 和 `weilai_token_last_update`。不删除旧数据，不按保存满 30 天推断服务端过期。新格式一次写入完整状态并检查写入结果。

HTTP 401，或 HTTP 200/403 携带明确认证错误码时，会标记当前凭据不可用。普通 403 只报告访问被拒绝，不作废凭据，避免临时风控导致以后每天都无法签到。重新观察同一失效凭据不会解除标记，需要重新登录并抓取新凭据。其他尚未验证的错误码统一报告未确认，不猜测含义。

限流等待或请求在途期间，若抓到了不同 Token、凭据被标记失效或存储不可用，旧任务停止，不自动切换账号继续提交，也不将旧账号的响应作为新账号结果。

日志不打印完整 URL、Token、服务端错误原文或完整响应；本地存储仍包含登录凭据，请勿分享。脚本不会读取或改写车辆控制、订单、消息数据。

Surge 离线测试覆盖首次抓取到定时执行、日志与通知、累计别名及数字字符串、零值与字段优先级、凭据轮换、失败处理、版本和配置一致性。

```sh

node --test weilai/tests/checkin.test.cjs
```

测试使用虚拟时钟、模拟客户端和虚构凭据，不发送真实请求。依据 2026-11-03 抓包整理了成功响应的非敏感字段；未把 HAR 或登录凭据放入仓库。认证失败、限流等样例是构造测试，尚需真机验证接口和客户端运行环境。

运行时接口依据 [Surge 官方脚本接口文档](https://manual.nssurge.com/scripting/api.html)。兼容 JSC 没有 `clearTimeout` 的环境；迟到回调由结束标记忽略。

## Egern 原生版 3.1.3

安装地址：

```text
https://raw.githubusercontent.com/atopsecret/SurgeScripts/refs/heads/main/weilai/weilai-auto-checkin.egern.yaml?v=3.1.3
```

1. 导入原生 YAML，并安装、信任 Egern 当前 CA。解密只追加三个既有蔚来主机与已知业务路径，不扩到车辆控制域名。
2. 在 Egern 下重新打开已登录的蔚来 App 的签到或个人页面。请求脚本只读取 Authorization 与 UA，不读 body、不签到；新凭据保存后发简短无声提醒，30 秒内不重复提醒，同 Token 同 UA 不重写凭据。
3. `蔚来自动签到 · Egern` 是 `schedule`，cron 为 `0 9 * * *`。需要立即执行时手动运行这条定时任务；不是运行 generic，也不使用伪造域名。
4. `蔚来本地诊断 · Egern` 是 generic，只读本地状态，返回合法 widget 并写日志；不发通知、不发送签到、不显示 Token。
5. `蔚来统计观察 · Egern` 是 response 钩子，只读取现有固定签到端点的成功响应。它不发送请求、不重新抓取凭据、不修改响应内容，也不写签到任务锁。

3.0.1 把必要存储改为 `ctx.storage.set()` / `get()` 原始字符串回读，避免 `setJSON()` / `getJSON()` 的对象键顺序差异。3.1.3 进一步修复捕获入口的误报：字段等价的回读可确认，更新的同凭据快照可合并；回读是其它新凭据或失效状态时，让旧捕获退出，不回写旧快照、不报告本次成功。写入前后仍停留在原快照、状态缺失、格式损坏或 API 异常时，明确报告失败，不盲目重试。

同 Token 同 UA 没有需要更新的业务内容，3.1.3 不再因每个 App 请求重写 `observedAt`。该时间从未用于推断服务端 Token 过期；同凭据的失效标记、`generation` 和当日确认仍保留。任务锁、失效标记及签到确认的严格写入校验没有放宽。

捕获脚本日志现在包含实际执行版本和固定结果码。可选 `weilai_egern_capture_status_v1` 只存版本、记录时间和结果码；本地诊断会显示该记录，以及可用时的 Egern App 版本。诊断记录故障不作废凭据、签到记录或统计。更新后先打开 App，再运行诊断，区分历史通知和新捕获结果：

- `C-SAVED`：已核验保存。
- `C-UNCHANGED`：凭据及 UA 未变，无需重写。
- `C-COALESCED`：已有更新的同凭据快照，保留它。
- `C-SUPERSEDED`：其它请求已更新当前状态，旧捕获退出。
- `E-READ` / `E-WRITE` / `E-READBACK`：分别是捕获前读取、写入、写后读取 API 异常。
- `E-EMPTY` / `E-FORMAT` / `E-MISMATCH`：分别是写后缺失、格式异常、未匹配到本次更新。

这些码不包含 Token、账号、请求 URL、响应正文或异常原文。保存失败通知只给出结果码与本地诊断入口，不再将所有错误写成“本地写入未确认”。现有凭据键、提醒键、统计键和任务记录键均不变，不需要清空存储或重复签到。

捕获、统计观察、定时与诊断四个入口使用同一个已核验的完整提交地址，避免 GitHub Raw 的 `main` 缓存或客户端旧脚本缓存。模块本身仍可跟随 `main` 更新。重新载入配置并更新模块后，运行“蔚来本地诊断”确认显示 `Egern 原生脚本 3.1.3`；仅打开 App 不保证模块与脚本缓存已经更新。相同凭据捕获会保持静默，以本地诊断的“已捕获”及新版捕获记录为准。

3.1.1 的提醒时间单独保存在 `weilai_egern_capture_notice_v1`，只存时间戳，不含 Token 或账号代号。提醒记录损坏时重新记录；提醒读写或通知 API 失败不回滚凭据，也不影响签到任务。合并仅针对共享存储中可观察的连续更新；原生存储没有 CAS，不能保证完全并发的不同执行器绝不重复提醒。

### 当日累计统计与被动观察

3.1.0 补回旧版累计字段兼容，并增加独立观察记录 `weilai_egern_statistics_v1`。只有现有签到端点、HTTP 200、业务成功、`checked_in === true`，且请求凭据仍属于当前有效 `generation` 时才保存校验后的统计数字与固定字段类型。写入前重新核对凭据和 UTC+8 日界；不同代、昨日或未来的观察不用于今日统计。

观察记录不写 Token，不覆盖 `weilai_egern_checkin_v1` 的今日确认或任务锁。当日签到已确认但累计缺失时，诊断和去重通知可以补用同日、同代的真实观察值；已有合法数字和零值仍优先。没有累计值就保持“未知”，不会把昨日累计加一。

新签到记录保存可选字段类型，累计缺失时可直接从本地诊断查看，不必寻找运行日志。旧记录未保存这项元数据时仍可使用；可选字段类型损坏只降级诊断，不使有效的签到确认失效。

更新后可以打开蔚来 App 的签到页，再运行本地诊断。是否产生这个端点的响应、是否成功解密、响应是否带累计数，仍取决于 App 与服务器。打开页面不能保证立即补出统计；没有新响应时，等待下一次正常自动任务，不为统计重复签到。

观察入口 `body_required: true`、正文上限 262,144 字节、原生执行上限 5 秒。正文只读取一次；完整取得后，无论解析或本地保存是否成功，都显式回传原字节，不修改状态码或响应头。没有额外的 Promise 正文超时竞速，以免读取尚未取消却提前丢失原字节回传。流读取失败或原生执行超时后的处理由 Egern 控制，离线检查不能证明客户端内部缓冲行为。

定时采用 Egern 的设备时区。官方文档没有 Surge `wake-system` 的等价字段，本模块不写该字段，也不承诺锁屏调度完全相同。

### 凭据、幂等与任务锁

凭据只在 `weilai_egern_auth_state_v1` 保存，包含 Token、观察时间、失效标记、合法 UA 和 `generation`。新 Token 换一代，同 Token 保留失效标记与代号；同 Token 同 UA 不反复更新时间。A→B→A 也不会误认成原来的在途任务。不读 `weilai_auth_state_v1` 或其他旧 Surge 键。

任务记录 `weilai_egern_checkin_v1` 只存任务 ID、代号、锁时间、已确认日期/有限统计及可选字段类型，不重复存 Token。所有必要存储写入都回读确认；核心状态不可读、结构不符或加锁未确认时不发 POST。真实目标请求可修复损坏的凭据状态；损坏任务记录不自动删掉或当作空记录。可选观察缓存或诊断元数据故障不作废凭据、不删除有效确认记录。

**每日成功去重与到期锁是 Egern 3.0.0 新增，不是旧 Surge 2.1.2 已有能力。** 仅 HTTP 200、`result_code: success`、data 对象且 `checked_in === true` 才记成功。同代凭据在 UTC+8 当日已确认后，不再发送 POST，也不为缺统计重复提交。新代凭据不沿用旧代标记；没有可靠账号 ID，因此不声称同一服务端账号更换 Token 后仍严格按账号去重。

任务锁 30 秒到期。进入任务、真正调用 POST 前、响应与 body 返回后以及 429 等待后都重新校验凭据代号、失效标记和锁归属；变化后停止，不改用新账号继续旧任务。只释放自己持有的锁。网络、超时或解析结果未知时不标成功，保留短租约以防马上重复执行；到期不代表服务器没有处理过请求。

Egern `ctx.storage` 没有文档化的 CAS、事务或跨进程互斥保证。短同步读写与回读能防常见重入，不能证明跨执行器同时启动时绝对只提交一次。测试覆盖同上下文的重入和可观察的状态变化，不能替代实际客户端的存储作用域、持久化与并发验证。

### 请求和失败处理

- 原生 `ctx.http.post` 使用原有固定端点、`event=checkin` 表单与秒级时间戳；`timeout: 5000` 为毫秒，`redirect: manual`、`credentials: omit`、`insecureTls: false`。不自动带 Cookie 或沿跳转把 Authorization 发给其他主机。
- 每次请求与响应 body 读取共用 5 秒，整个任务预算 24 秒，YAML 上限 30 秒。Promise 兜底限制异常挂起；没有文档化 AbortSignal，不能说兜底超时已经取消服务端收到的 POST。
- 只有明确 429 按严格整数秒或标准 HTTP 日期等待，至少 1 秒、最多 3 次，并受同一总预算限制。网络失败、5xx、跳转、未知 JSON/业务状态不自动重发。
- 401 或 200/403 的明确认证码才标记失效。普通 403 不作废；5xx 即使夹带认证字样也不作废。迟到旧响应不写新代凭据或新代今日记录。
- 确认成功但每日记录未确认保存时，仍如实报告服务器确认结果，并明示本地防重复未保存，不把失败记录当成功缓存。统计字段与 Surge 版一致；纯数字字符串转换后，任务记录只保存规范化的数字。当日真实观察只能补缺失项；仍缺失时显示“未知”，不为补统计重发签到。
- 日志和通知仅本地固定文案及校验后的数字，不输出 URL、Token、任意异常或服务端原文；不宣称本次获得了新奖励。
