## 京东实现

- 显式补 `uniformRecommend0`、`uniformRecommend6`；两端静态规则支持非首参数，拒绝 ID 前缀、重复键及裸重复键。编码参数键保守放行，普通参数值保留 URL 编码能力。两份静态本地规则按条验证一致。
- 共用 `jd-policy.js`，构建生成独立 Surge、Egern 与可选 POST 关联脚本。运行时不导入外部公共脚本；`build.mjs --check` 同时检查缺失和过期产物。
- 统一 basicConfig 根层和 `data` 包装、失败放行、lite 键名处理与冲突保护、混合列表容错及五个精确 MITM 主机。
- 新增 `orderTrackBusiness`、`getTabHomeInfo`、`myOrderInfo`、`personinfoBusiness`。只清已知推广，不复制个人工具栏保留名单和排序，不改客服提示、评价提醒、钱包或未知工具。
- 十二类接口均验证双端处理结果和幂等。开屏继续只清广告字段，普通商品图片不匹配开屏专用尺寸；不宣称模块能清除 App 缓存。
- Egern 单次 `arrayBuffer()`、严格 UTF-8、原字节回退；Surge 使用 `binary-body-mode=true`、`full-header-mode=true`、`engine=webview`。仅处理完整 HTTP `200` 与支持编码的 JSON。失败正文、无变化和处理异常保留；改写后清理过期正文头，保留未触及的多值 Cookie 和业务头。
- Surge 官方响应脚本不提供请求正文。无查询字符串的 POST 捕获在模块中整行注释，默认关闭；明确启用后才以稳定请求 ID 关联，最多 64 项、有效期 60 秒。超限请求正文会被 Surge 终止，存储没有 CAS；这些限制在说明中保留，不把可选能力描述成默认已启用。

重点回归还包括转义 JSON 身份键、未知导航、无效 UTF-8、BOM、序列化异常、一次性响应流、响应头失败恢复、请求身份隔离、缓存消费删除与存储异常。

## 菜鸟实现

- 四个明确广告请求迁移成空体 `404`，附带 `X-Cainiao-Cleaner-Version`，精确限定五个主机与完整 API 名，支持数值版本路径（含 `/1.0/`）。
- 三组响应清理：page.fetch 的搜索热词与运营列表；仅 e2e `.fetch.cn` 的 banner/activity/vip；龙泉 `780001` 广告位的 `contentList`。e2e `.fetch.cn` 同时执行普通 page.fetch 的共同字段处理，保留来源主机差异。
- 未迁移 netflow 的“首项 materialId 不符合就整包 data={}”规则；也未把活动 LPX 没有引用的旧 JS 算作当前覆盖。
- 列表只处理数组，运营卡片只处理对象或数组。查件、寄件、取件码、订单、钱包和未知工具及其顺序保持；不封整个阿里、淘宝或菜鸟共用域名，不改 HTTPDNS。
- 原生入口、单次读体、严格 UTF-8、原字节回退、HTTP/业务失败、响应头与多值 Cookie 保护、静默诊断均有离线验证。头更新失败回传原正文，不计作成功改写；本地诊断仅保存固定路由、枚举和封顶数字。
